# 怎么少返工

用户最烦的不是改，是退回重做。2026-11-06 统计了 22 个会话（589 条用户消息）和各项目的反馈记录：日志里约 108 次退回（±15），其中 32 次是整个方向被否。下面是原因和后来真正管用的做法。

这些是做法，不是规矩。片子需要时可以不这么做；但要是用户开始说「都不满意」「不如之前」，就回来对照一下。

统计是一个人按主因编码的，只能看量级；第 2、3、4 类边界模糊。

| 原因 | 次数 / 方向级 | 代价 |
|---|---|---|
| 靶子不清，方向对不上 | 24 / 17 | 丢整版 |
| 片段单看没问题，连着看才暴露 | 21 / 3 | 重渲 |
| 改版冲掉已认可内容 | 21 / 2 | 丢掉用户喜欢的东西 |
| 质感不够 | 20 / 3 | 局部重做 |
| 听错、丢上下文 | 9 / 0 | 用户要重复说 |
| 故事脱离歌 | 8 / 3 | 故事和分镜全换 |
| 口味被升格成规矩 | 5 / 4 | 后面的版本整体跑偏 |

## 1. 开工前用现成成片对齐方向

用户要看到成片质量才能判断。概念图、粗分镜都被说过「像 PPT」「粗糙」，所以不要拿草稿对齐，拿已经存在的成片：别人的片、用户的旧作、之前的版本。

- `film.py target add 参考.mp4`，在挑选页上带声音看，用户说要不要、要的是哪一点。《蜈蚣》给了三支参考之后，方向级退回从 4 次降到 0
- 用户明确说「你定」时，可以自己定方向直接做样片。只给了一首歌、没说别的时，花一分钟拿两三支现成成片问一句更省事。连续两轮方向被否，就停下来要参考，不要再猜第三版
- 用户说「都不满意」或说不出哪里不好时，先问比什么差，拿几支片让他指

## 2. 每次改完连着看

单段看没问题、接起来就「割裂」的情况很多（《怪物》07 段连退三轮）。

- `film.py assemble` 几秒就能按当前选择拼出带声音的连播，用它看，也给用户看这个，不要只发改动的片段
- 改一处要连着前后镜头一起看。`tools/qa/seams.py` 查接缝，`flowcurve.py` 查速度
- 我们听不到声音，只能报测量值，卡没卡上由用户判断

## 3. 认可过的东西不要动

- 每版都用 `film.py add` 收进来，不覆盖。用户认可的段落 `film.py lock`，之后 `add` 新版时会自动比对，动到了就报出来
- 要退回某一版：`film.py restore v12` 解出当时的代码，现有文件不动
- 用户在几版之间拿不准时，开 `film.py page` 让他逐段挑，别替他选。他喜欢的常常是各版里零散的瞬间，所以有「记下这一刻」
- **没标的段落按没认可算**。`film.py plan` 会列出来，不能写成「照搬」
- 只重渲改动的片段（《怪物》之后用户明确要求的）

## 4. 质感问题多半是主物件糙，不是画质

- 「粗糙」通常是场景里的东西糙。先看主物件是不是程序拼的简单图元，换细节足够的模型或素材，别先调渲染参数
- 交之前在原尺寸、连续帧里看新加的东西，把它和靶子的同类画面并排（`tools/compare.py`）

## 5. 故事跟着歌走

《怪物》有一版评委打 8.5 分，用户说「完全跑偏了，跟歌没关系」，故事和分镜全部作废。

- 定故事之前先按段落对歌词意群（只用行号），最响的段画面最满
- 评审要逐段对歌，高分不代表用户认可

## 6. 听懂再动手，把用户的话存下来

- 意见看不懂就先复述。方向级的改动先用 `film.py say 段号 "我打算……"` 写出来，让用户在页面上点对或不对（《怪物》之后，通宵整片只剩局部意见）
- 用户的原话、范围、日期记进项目的 `docs/TREATMENT.md`。会话会被压缩，每段开工前重读

## 7. 一句口味只管它说的那一处

- 记意见要带出处和范围：哪一镜、哪一段、哪一版。「简洁」「太滥用隧道」这类话不要升格成全片规矩，用户也会改口
- 模糊的意见（「不够高级」）先按最可能的原因在那一处改一版给他看
- 引擎的文档也一样：这里写的各片教训都带出处，换一支片不一定成立

## 8. 评审是帮手，不是门槛

独立评审能挑出「看着普通」这类自己看不出的问题，也改坏过东西（《怪物》「评审改坏了」，退回样片 e）。

- 缺陷直接改；动到口味的（主视觉、构图、概念、字体、配色）先问用户
- 锁定的段落评审不碰
- 不用分数决定要不要继续改，用户认可才算数。提示词见 `docs/检查和评审.md`
