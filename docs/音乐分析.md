# 音乐分析

把一首歌变成节拍、段落、鼓点、逐词歌词的数据。在项目根目录运行，结果写进 `audio/` 和 `data/`：

```bash
python <引擎>/analysis/run.py 歌.flac
```

已有结果的步骤会跳过，`--force` 重跑，`--only separate,analyze,lyrics,events` 只跑某几步。它不打印歌词。

依赖：numpy、scipy、librosa、soundfile、torch、torchaudio、audio-separator、opencv-python、Pillow、fonttools。分离模型共用引擎的 `analysis/models`，第一次运行时下载。

纯音乐也能跑：没有歌词就跳过对齐，`events.py` 见人声轨比整曲低 30 dB 以上就不出人声切片。

## 结果

| 文件 | 内容 |
|---|---|
| `audio/song.wav` | 44.1 kHz，所有时间都以它为准 |
| `audio/stems/` | 人声、伴奏 |
| `audio/stems4/` | 鼓、贝斯、其他、人声 |
| `data/audio.json` | 拍、强拍、段落、包络、起音 |
| `data/lyrics.src.lrc` | 内嵌歌词原文（不进对话） |
| `data/lyrics.json` | 逐词时间 |
| `data/events.json` | 底鼓、军鼓、镲、贝斯进入、riser 等每一下的时间 |

## 要核对的

- **速度：** `analyze.py` 在 60–200 BPM 里自动找，打印候选和排除理由。半速、倍速不对时加 `--bpm 大概的速度`，或写进 `data/song_config.json`。残差（`kick residual sd`）一般 5–15 ms，`drift` 突然变大说明中途变速。
- **小节和 drop：** Falling_Again 的 drop 判早 1.55 秒，Clarity 切点早一小节，都是看成片才发现的。有 `app` 时可以 `cd app && bun scripts/render.ts beatcheck` 出节拍校验片，让用户听。
- **段落：** 默认只有一整段。需要时跑 `python <引擎>/analysis/analyze.py --bars` 看每小节的表，或用 `analysis/structure.py` 出草稿（SongFormer，独立环境，先跑 `analysis/setup_structure.py`；权重不能商用，接商单的片子手填，见 `docs/模型选型.md`）。结果写进 `data/song_config.json`：

```json
{"bpm_hint": 134, "section_bars": [["intro", null, 8], ["verse", 8, 24], ["drop", 24, null]]}
```

## 单独跑某一步

| 脚本 | 做什么 |
|---|---|
| `analysis/separate.py vocals` / `demucs` | 分离人声 / 四轨 |
| `analysis/analyze.py [--bars]` | 节拍、段落、包络 |
| `analysis/ctc_align.py` | 逐词对齐。只支持英文；和英文行同一时间戳的中文行作为译文保存。长歌用环境变量 `CTC_T0`、`CTC_T1` 分段 |
| `analysis/snap_words.py` | AI 生成的歌（人声卡得很准）把词吸附到 16 分音符格 |
| `analysis/events.py [--bars]` | 声音事件。要在歌词对齐之后跑，歌词时间改过就重跑；阈值不准就调 |
| `tools/qa/hitcheck.py` | 从分轨直接量击打，和切点比（比事件更细，排硬切时用） |

歌词文件的行时间可能差 0.2–0.5 秒（《蜈蚣》），字幕要贴人声的话用 `audio/stems/vocals.wav` 量起音，或用 `lyrics.json`。
