# 质量验收清单

> 前身是 `~/.claude/MV去AI味.md`（2026-10-01，原文存档在本地 `docs/archive/`，不进仓库）。2026-10-03 按用户意见改写：「去 AI 味限制了你的发挥」「一镜到底穿越、无限放大其实不错，现在 Opus 审美很好」。
> **现在的用法**：设计时放手做，不设手法禁区，也不要求事先证明某个手法用得对；这份清单只在每轮预览时用，查成片有没有缺陷。查出来的问题按缺陷修，不按「像不像 AI」判断。

## 一、成片要达到的

1. **跟着整首歌走。** 主歌、副歌、间奏、drop 的画面密度和能量对得上歌；人声的长音、气口、重音有回应；整片有起伏（密度、景别、色调），不是一个强度从头到尾。
2. **焦点清楚。** 每个时刻观众知道该看哪里；缩到手机竖屏、小窗也读得清。
3. **动作有重量。** 有预备、过冲、跟随；不同材质的东西动起来不一样。
4. **歌词读得清、跟得上。** 唱到时字已经在画面里；逐字 / 逐词跟人声起音，不提前跑在人声前面；中文按中文习惯排，不一整句同时蹦出来。
5. **经得起暂停。** 任何一帧没有穿模、溢出、错位、闪烁、糊字、空帧。
6. **技术过关。** 见第三节。

## 二、用户以往的意见

- 「表现力不足、有劣质感」「效果太烂」→ 焦点、动作、细节（第 2、3、5 条）
- 「狙击镜段单调」→ 起伏（第 1 条）
- 「歌词延迟」、中文「不要一整句同时出现」、英文在隧道里「表现不好」→ 第 4 条
- 「键盘切到赛车时镜头卡一下」→ 第 5 条
- 「最后的收尾不好」→ 结尾要落在歌的结构上（第 1 条）
- Falling_Again v4：「场景太多太碎、画面质感不够、运镜看不明白、冲击力不够」→ 第 1、2 条
- 「约束你设计的全部去掉，你自己来」「去 AI 味限制了你的发挥」→ 本清单只验收，不规定怎么设计

## 三、每轮预览自查

**看片**（每个场景抽几帧，整片出一张联系表：`render.ts sheet`）

1. 每帧的焦点在哪？缩到 360 宽还看得清吗？
2. 联系表排开，整片有没有起伏？哪一段的密度和歌对不上？
3. 主体够大吗？有没有被挤到画面边缘、太暗看不清、同色叠同色（红底红字）、歌词压住主体？
4. 跟随主体的效果（光圈、放大、聚光）在镜头移动后还跟得住吗？这类效果统一走一个「世界坐标 → 屏幕坐标」的函数，不手写屏幕坐标
5. 关键动作（交接、落地、撞击、变形、转场）按 0.2 秒间隔抽帧条放大看；联系表每 1–2 秒一帧看不出这些问题
6. 暂停任意一帧：穿模、溢出、糊字、空帧？

**技术**（脚本见 `tools/qa/`，用法见 `docs/模块目录.md`）

- 响度和真峰值：发布版约 −14 LUFS，真峰值 −1 dBTP 以下
- 大面积闪光每秒不超过 3 次
- 转场空帧：`blackdetect`
- 卡点偏差：场景导出的关键动作时间点和 downbeats 逐个比，看偏差毫秒数
- 用抖音常见码率重编码一遍，看暗部色带和细节
- 编码色彩：输出要按 BT.709 转换并打标签（引擎的 `render.ts` 已处理；外部重新编码时别丢）
- 首尾帧能否循环（需要循环时）
