## 一、先定时间网格

参考片能在 100 秒里切十几种画风还不散，靠的是结构而不是哪个特效：

- **一小节一个镜头格**。150 BPM、正好 63 小节，右上角的「06/63」就是小节号；切点 64% 落在拍点 ±40 ms。用 `audio.timeOfBar(k)` 排 `timeline.ts`，用 `cues()` 登记关键动作
- **一个主角，多种画法**。颜文字是有零件的模型（左右括号、眼、嘴），每种画风只是换一种渲染。主角统一，画风再多也连得起来
- **HUD 讲故事**。小节号牌、终端弹窗、监控面板、计数器把剧情交代清楚，画面就可以放开做抽象

## 二、后期参数（场景 `return` 即可，默认全关）

这些参数在运动模糊平均之后、每帧只算一次，随机图案按帧号换（`frameIdx`），导出确定。

| 参数 | 效果 | 复刻参考片用的值 |
|---|---|---|
| `crt` | CRT：曲面玻璃、扫描线、RGB 栅格、闪烁、圆角黑边；HUD 也在玻璃上 | 1 |
| `crtCurve` | 曲面程度（乘以 crt） | 开机段 0.25，平时 0.12 |
| `crtLines` | 扫描线条数（占满画面高度） | 粗线 120，细线 200–270 |
| `crtNoise` | 信号衰减：去色、横向拉丝雪花、行抖动、滚动暗条 | 崩溃段 0 → 0.8 |
| `crtOff` | 关机：0 → 0.55 压成一条亮线，0.75 → 0.97 缩成点后熄灭；反过来跑就是开机 | 关机那一拍 0 → 1 |
| `glitch` | 数字故障：水平切片错位、宽条块位移、少量换通道、黑块、色差 | 跟着底鼓：`0.85 * audio.ev.pulse('kick', t, 0.06)` |
| `glitchSort` | 像素排序竖向拉丝 | 跟着军鼓脉冲 |
| `glitchSeed` | 换一组故障图案 | 每个镜头一个 |
| `vhs` | 录像带：行摆动、滚动跟踪噪声带、色度拖尾右偏、底部磁头噪声 | 倒带段 0.6–1 |
| `bw` + `invert` | 冲击帧：纯黑白（`bwThreshold`）；加 `invert: 1` 是白底黑形 | 打中的那一拍，1–4 帧 |
| `pixel` | 像素化（块大小，逻辑 px），辉光保持柔和（Hi-bit 感） | 6–12 |
| `pixelLevels` | 每通道色阶 + 4×4 有序抖动 | 4–8 |
| `pixelGrid` | 像素块之间的暗缝（点阵 LCD），pixel ≥ 3 时有效 | 0.5–1 |
| `letterbox` | 上下黑边占画面高度的比例 | 0.12–0.25 |

开了 CRT 时，中文字幕层（`zh` 叠加层）留在玻璃外面，不弯不吃扫描线；参考片关机时屏外提示字就是平的。

## 三、场景级模块

下面每个模块在 `?ref` 十段里的实际用法比这里的片段更完整：字符画看 `ref_crash.ts`，万花筒看 `ref_kaleido.ts`，叠层字看 `ref_stack.ts`，音游看 `ref_rhythm.ts`，字符粒子看 `ref_boot.ts`，像素世界看 `ref_stage.ts`。

### 字符画 `engine/ascii.ts`

原片：开机脸、环隧道都是“形状 → 字符网格”，括号绿、眼白、ω 粉，字符行之间有缝。

```ts
asc = new Ascii({ chars: ' .:-=+*#%@' });          // init 里建（字体已加载）；只要一种字就 ' @'
// 先把形状画进 makeRT() 的 pic，再：
asc.render(renderer, pic.texture, out, { cell: 15, mode: 'color', boost: 1.5, threshold: 0.06, gamma: 0.8 });
```

- `mode: 'color'` 字随原色；`'mono'` 单色荧光（`ink`）
- `cell` 是单元格高度，推镜就是放大 `cell`，滚屏就是改 `offset`
- 纯色色环用 `' @'` 并设 `dither: 0`，否则环上会有随机空格
- 再叠 `crt: 1` 和 `bloom: 0.9, bloomThreshold: 0.45`

### 万花筒、无限缩放、虹膜转场 `engine/warp.ts`

- **Kaleido**：`mode: 'polar'`（N 折镜像，曼陀罗）或 `'tile'`（镜像墙纸；原片进入万花筒前先是 3×3 镜像墙）。源图要**密**：颜文字零件、叶子、彩色同心色环（同心圆会变成色带）。中心徽章画在万花筒之后，不参与镜像
- **Droste**：源图是一张中间挖空（透明）的画框；`scale` 是内层大小（0.84 层数多、0.76 层数少），`twist` 是每层转角（0.1 左右就是原片的旋转画框隧道），`phase` 随时间增长就无限推进。源图要先 `clearRT(…, 0)` 再用 `comp.draw` 画进去（预乘 alpha）。中心太阳这种固定元素画在之后
- **Iris**：`iris.render(renderer, under, cur, out, { p, ring })`，圆形（或圆角框 `box`）窗口里换画风，原片 59 秒的转场就是这样

### 文字特效 `kit/textfx.ts`

- `ringText`：字沿切线排一圈；`fill360` 重复铺满整圈；每环自己的转速、正反方向交替 → 唱片（原片 40 秒）
- `pathText`：沿折线排字（波浪字幕带、轨道上的字）
- `stickerText`：填色 + 粗圆角描边 + 实心偏移阴影（Memphis 贴纸字）
- `stackText`：彩虹叠层挤出。`vanish` + `depth` 让层朝消失点收缩，`layers` 20–30，`bandW` 等于正面描边宽，色带才连成一片；不要给每层加黑描边（那样像一块块板）；`hollow` 加间距就是彩色残影
- `crackText`：从字里一点放射出白色裂纹，带黑边（原片修复段）

### 音游 `kit/rhythm.ts`

```ts
hw = new Highway({
  notes: notesFromEvents(audio, [['kick'], ['snare', 'clap'], ['hat'], ['vocal']]),   // 每条轨取哪些声音事件
  env: (t) => audio.env('rms', t), markers: [{ t: audio.timeOfBar(45), label: '46 · GUARD v2.0' }], since: this.ctx.start });
hw.draw(ctx2d, f.t);
```

音符就是 `data/events.json` 里的真实鼓点（也可以手写 `notes`）；打中时判定牌、PERFECT、红色闪条、连击数、分数都由时间算出。默认四条轨照原片的位置（中间留空给大脸），跑道表面是随包络起伏的山脊线（越远越高、每 23 行一条红线），远端一块红色终点。完整用法见 `scenes/ref_rhythm.ts`。

### 字符粒子 `kit/glyphfield.ts`

开机段的核心：几千个字符在 3D 里翻转飞散，再飞回落成字符脸。

- `cellsFromCanvas(canvas, atlas, { cell, only: ' .-=+*#%@', lum: 'max', gain })`：把画好的形状变成字符格（落点）。`only` 限定只用符号（原片的脸全是 `- = + * # % @`）；`lum: 'max'` 让饱和的粉、绿也算亮，才会用上 `# % @` 这类密字
- `GlyphParticles(atlas, max, { size })`：一次实例化绘制，`set(i, x, y, z, rx, ry, rz, scale, glyph, colour, alpha)`
- 拖尾：同一个粒子在 `t − k·dt` 的几份淡化副本（`ref_boot.ts` 的 `state()` + `TRAIL`），仍是 `f.t` 的纯函数；再叠导出时的运动模糊
- 形状要画成**软边 + 上亮下暗**，网格里才有边缘的 `= - +` 和内部的 `# % @` 层次
- 眨眼：把离眼睛中线远的字符行关掉（不要把字挤在一起：加法混合会叠成亮团）

### 像素世界 `kit/pixelstage.ts`

bad-time-mv 的核心：低分辨率像素画（默认 480×270，最近邻采样）是一块平面，被真正的 3D 相机拍。

```ts
st = new PixelStage(480, 270);
st.world.clear(); /* 画像素画（透明底！） */  st.emi.clear(); /* 只画会发光的（同样的线、心） */
st.render(renderer, out, { x, y, zoom, roll, pitch, yaw }, { t: f.t, glow: 1.2, grid: 0.5, voidAmt: 1 });
```

- 世界画布要**透明**清空，远处的点阵虚空和漂浮小方块才露得出来
- `emi` 只画发光体，乘 `glow` 进辉光；相机常带一点 `roll` / `pitch`，画面就是梯形
- 放大时 `grid` 显出像素点阵
- 第一人称体素段用引擎的 `voxel.ts` 渲到低分辨率，再配 `pixel` 后期参数

共通的经验：

- **先量再画**：每段先用 `tools/refmatch.py sample` 取颜色、`grab` 存全分辨率帧量尺寸，再写代码。凭印象写的第一轮总是“方向对、比例全错”（字大小差一倍、主体位置偏、颜色太艳）
- **最常见的差距**：主体比例和画面占比（几乎每段第一轮都要改）、背景太干净（原片都有噪点 / 半调 / 网点纹理）、颜色太饱和或太亮、运动太均匀（原片是先快后慢、按拍顿住）
- **线性空间**：`Compositor` 的 `opacity` 是线性的，想“看起来 15%”要用 ~0.015
- **冲击帧关辉光**，否则光晕被阈值化成黑团
- **大于画面的物体**（唱片、远景）要画在比画面大的画布上再缩放，否则缩小时是方的

## 五、逐帧对照复刻（做到像，而不是做到有）

教训：只验证“这个效果有没有”（早期的 `?retro` 演示），做出来远不如原片。`?ref=…` 十段的做法：

工具：`tools/refmatch.py`（用法见文件头）。

1. **抽原片**：`refmatch.py frames 参考.mp4 --from a --to b --fps 10 -o …` 排成联系表；`grab --t …` 存全分辨率关键帧放大看字形、字号、行距
2. **量数据**：`refmatch.py sample 参考.mp4 --t 57.4 --pt x,y --box x0,y0,x1,y1` 取颜色；量尺寸（字高、格子、主体位置和占比）、时间点（每个动作在第几秒），写成规格（findings.md E、F 节就是样子）
3. **写场景**：按规格写，关键时间点用常量（`const ENTER = 0.8, BURST = 0.98 …`），场景本地时间 = 原片时间 − 起点
4. **并排对照**：`refmatch.py sheet 参考.mp4 --ref-start 56.0 --t 0.1,0.25,… --query ref=名 -o …`（Python 找不到 bun 时先用 `render.ts stills` 出图，再加 `--ours 目录`），8–12 个时刻，逐格写差距：构图、大小、颜色、密度、亮度、动作阶段
5. **改、再渲、再拼**，直到差距只剩“原片自己的偶然”。十段用了 2–5 轮
6. **最后渲视频对照**：`render-par.ts --query ref=名 …` 出片，`refmatch.py video 参考.mp4 --ref-start … --ours …` 拼成左右对照（原速几遍 + 慢放一遍）；静帧看不出节奏

## 六、已知限制

- **颜文字字形**：中文回落字体（`make_fonts_zh.py`）只收“带汉字的字符串”里的字，`٩ ۶ ง ´ ♡ ≧ ≦ ▽` 等会落到系统字体，风格不统一（不会缺字）。要统一，就在项目 `config.ts` 的 `EXTRA_FONTS` 加一套覆盖颜文字的字体
- **CRT 玻璃外的文字**：只有中文字幕层留在玻璃外；场景自己画的字都在玻璃上
- **荧光余辉**（参考片开机时文字有重影）：用导出时更长的 `--shutter` 近似，没有单独的余辉缓冲（那样就不是 `f.t` 的纯函数了）
- 参考片关机亮线会跟着音频起伏（像示波器），引擎里只有直线；要的话在场景里自己画
