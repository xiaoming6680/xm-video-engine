# 检查和评审

查缺陷用，不规定怎么设计。脚本都能在项目根目录原地跑：`python <引擎>/tools/qa/…`。

## 交付自检

可选：想在交出去之前过一遍时用。它不打分、不管画面风格，也不规定流程：只有**技术**和**卡点**两项算问题（退出码 1），其余各项列在「参考」里，没用就写「没用」，不算问题：

```bash
python <引擎>/tools/qa/selfcheck.py [成片]        # 默认取 film.py 最新收的那一版；写 out/qa/自检.md
python <引擎>/tools/qa/selfcheck.py 成片 --quick  # 不替你跑要开浏览器的曲线图和卡点导出
```

| 项 | 查什么 |
|---|---|
| 技术 | `check_video.py` 全过（自检替你跑） |
| 看片材料 | 联系表、运动量曲线、动作最大三处的洋葱皮（自检替你生成） |
| 看片笔记 | `out/qa/看片笔记.md` 比成片新，并且按文件名写到了每一张图：Read 打开，写看到了什么、要不要改 |
| 运动量跟歌 | 各段画面运动量和歌的响度等级相关 ≥ 0.3 |
| 动作曲线 | `render.ts curves` 比成片新（自检会试着替你跑）；有 `kfe` 轨道，没有全对称的 |
| 卡点 | `render.ts cues` 比成片新；场景登记了关键动作，偏差在一帧内 |
| 候选 | 多数段落有两版以上可挑（`film.py`） |
| `确认`（自检里的项名） | 没标的段、等确认的「我打算」列出来，交给做片的人 |
| 动作表 | 项目的 `docs/TREATMENT.md` 的「动作表」填了，行数够分段数 |
| 独立评审 | `out/qa/评审*.md` 比成片新（评审的回复存成这个文件） |

技术和卡点的问题该修就修；参考项有没有用、要不要补，看这支片需要。2026-11 的对照实验里，同一段音乐两个不用引擎流程的 Agent 和两个照这些流程做的 Agent，盲看排名打平，后者多花约 1.5 倍 token、2–3 倍时间，所以这些不再是必做项。

## 技术

```bash
python <引擎>/tools/qa/check_video.py 成片.mp4 [--song 歌 --start 0] [--lead 片头秒数] [--hits 12.4,31.0] [--douyin out/测试.mp4]
```

| 项目 | 说明 |
|---|---|
| 真峰值 | −1 dBTP 以下，防止编码后爆音。音量不压低，保持歌的母带响度（B 站、抖音不统一响度，压到 −14 LUFS 会比别人小一截）。AAC 过冲时限幅器压不住，先整体降几 dB |
| 音画偏移 | 成片音轨和原曲做互相关，应为 0。片头有卡片时加 `--lead`，否则会误报。外部混流别丢 AAC 的 edit list |
| 空帧、黑场 | `blackdetect`。设计内的黑场不算问题 |
| 色彩标签 | BT.709。外部重新编码时别丢 |
| 闪光 | 3×3 分区，列出每区每秒超过 3 次的地方。只报告，不影响退出码。超了要告诉做片的人，由他定：可以加警告卡，也可以改画面（快切换底色时拉近亮度、连击用同一底色、频闪的黑帧减少或改成压暗）。公开发布前要确认平台要求 |
| 重击 | `--hits`：手机频段（350 Hz–9 kHz）排在全片最响的 5% 里。歌本身的混音改不了，自己加的音效按它调 |
| 缺字 | 有 `app` 时 `render.ts glyphs` 应为 0 |

## 看片

先带音乐、原速、从头到尾连着看（我们听不到声音，就抽帧看，并如实说明），再看单帧和报告。

| 工具 | 查什么 |
|---|---|
| `tools/film.py assemble` | 按当前选择拼连播，几秒钟 |
| `tools/qa/review.py 视频` | 联系表、运动量对 RMS 曲线；`strip 起 止 张数` 出动作帧条；`onion 起 止 张数` 洋葱皮（一段动作叠成一张，间距就是速度）；`frames [起 止]` 逐帧表（每一帧都在、一秒一张、标帧号，加帧差尖峰表，拆参考片手法用）；`rhythm [起 止]` 节奏质地（每秒切点、完全停住的帧占比、停顿长度，和参考片各跑一次对照） |
| `cd app && bun scripts/render.ts curves` | 场景里 `kfe` 关键帧的曲线图：值、速度、拍点、切点；逐段说是快出慢停还是对称缓动，关键帧离拍点几毫秒，全对称的标「可能发飘」 |
| `tools/qa/seams.py 视频` | 每个切点前后的锚点、运动、亮度、色调、声音；`--ref` 和参考片同一处并排比 |
| `tools/qa/flowcurve.py 视频` | 光流速度、平移、推拉，标急停和抽动；`--ref` 对比 |
| `tools/qa/trail.py 视频 --segs a:b` | 长曝光：运动路径断没断 |
| `tools/qa/trackcheck.py` | 场景报了 `track()` 时查瞬移、交接 |
| `tools/qa/cuecheck.py` | 场景报了 `cues()` 时查卡点偏差 |
| `tools/qa/hitcheck.py --cuts …` | 切点和分轨里真实击打的偏差 |
| `tools/blender/verify_frames.py a b` | 两组序列帧比对，抓连续渲染偶发的整段变黑 |
| `tools/compare.py`、`tools/refmatch.py` | 和参考片并排 |

常见的问题（不一定都适用）：

- 焦点：每帧观众该看哪？缩到 360 宽还看得清吗？
- 起伏：联系表排开，一个强度、一种构图从头到尾就是问题
- 跟歌：主歌、副歌、drop 的密度和能量对得上吗？
- 歌词：唱到时字已经在画面里，不提前跑在人声前面；白云、亮天空上也读得清
- 暂停任意一帧：穿模、溢出、糊字、同色叠同色（红底红字）、歌词压主体
- 关键动作（落地、撞击、变形、转场）按 0.2 秒抽帧条看，联系表看不出来
- 跟随主体的效果在镜头移动后还跟得住吗
- 有角色时：手臂贴身、裙摆穿腿；近景跑 `render.ts scan` 查走光（抖音会限流）
- 截取片段的结尾：一般人声唱完收、伴奏淡出；`tools/held_note_ending.py` 是另一种做法（拖长最后一个音）

## 独立评审

自己看会顺着自己的设计看，所以交出去之前，可以让没参与制作的子代理或另一个会话挑刺。它是帮手，不是门槛：不靠分数决定要不要继续改，最后由做片的人判断。

- 缺陷直接改；动到口味的（主视觉、构图、概念、字体、配色）先给做片的人看一两张样张
- 锁定的段落和已经定下的事写进简报，评委在这个范围里挑刺
- 有参考片时逐段对照原片。只看自己的片子，评委挑不出方向偏了
- 评审要逐段对歌：分数高不代表方向对

提示词（换掉尖括号里的内容）：

```text
你是挑剔的评委，熟悉这支片所属类型的一流作品（动态设计就参照 Buck、ManvsMachine、Territory Studio、B 站 / 抖音头部设计账号；
动画、写实 CG、手绘等按各自的一流作品）。这支片不是你做的。按它自己的方向评，不拿别的风格当标准。
评得越具体越有用，客气没用。

片子：<视频路径>（<样片 / 整片草稿>，<平台和画幅>）。方向和已定的决定：<项目的 docs/TREATMENT.md>。
不能动的：<已定的口味决定和锁定的段落，一条一行>。在这个范围里挑刺，不要提议推翻。
参考片：<原片路径和对应时间段；没有就删掉这一行和第 2 步的对照>。

1. 先从头到尾看一遍（带声音；不能听就说明，并抽帧连着看），记下哪里走神、哪里接不上、哪里没感觉。
2. 再细看：联系表（python <引擎>/tools/qa/review.py <视频>）；最快、最重要的几个动作出帧条
   （review.py <视频> strip <起> <止> <张数>）；5–8 个关键时刻看全分辨率帧（边缘、字、锯齿、色带、纹理、裁切）。
   有参考片时逐段并排对照：文字怎么动、转场怎么接、画面密度和留白，每段写差在哪。
   逐段对歌：这段歌在说什么、能量多大，画面对得上吗。
3. 每项打 1–10 分，只作参考（5 = 学生作业，6 = 模板水平，7 = 扎实的专业水准，8 = 一流工作室，9 = 能入围奖项），不要虚高：
   概念和记忆点、跟歌、动作手艺、构图和字、质感、风格、连贯、技术。
4. 给 5–10 条修改意见，按对整体观感的影响排序。每条写：时间码；看到了什么；为什么要紧；怎么改（具体到手法和数字）。
   宁可几条大改，不要一堆小毛病。至少一条是提升惊艳度的。每条标「缺陷」还是「口味」。
5. 标出致命问题：看起来像模板或 AI 生成的、中文别扭、缺字或回落字体。
   画面要有实物感或手作感时，逐项找程序生成的破绽：同一尺度的噪声、等宽等距的线、绝对规则的点阵、完美对称、
   同一图形重复摆放、分布太匀、黑位死平、渐变太干净、边缘太齐。风格本来就要的干净和对称不算。

回复：打分表、致命问题、修改清单。
```

第 5 步的破绽清单来自《格物》（link1412/gewu）的盲审记录：模型评委混看渲染和真照片时挑出的破绽。

评审的回复存成 `out/qa/评审.md`（多轮就 `评审2.md`……），交付自检按它算「做过独立评审」。拿到意见后：先 `film.py add` 收下当前版本再改；缺陷改，口味问；重渲后亲眼看图，确认真的改到了，也确认没改坏别的；最后列出哪些改了、哪些没改、为什么。
