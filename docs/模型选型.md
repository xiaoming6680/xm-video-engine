# 模型选型

引擎里各环节用哪个模型、为什么，以及试过没换的。规则：**新模型不比现有的好，就继续用现有的**。2026-10-08 在 HuggingFace 上找了一轮，拿已完成项目（Clarity、Still_Shining、Falling_Again、暗叫、pdoom）验收过的产物当基准对比。

## 现在用的

| 环节 | 模型 | 许可 | 在哪 |
|---|---|---|---|
| 人声 / 伴奏分离 | MDX Kim_Vocal_2 | — | `analysis/separate.py vocals` |
| 四轨分离 | htdemucs_ft | MIT | `analysis/separate.py demucs` |
| 歌词对齐（英文） | torchaudio MMS_FA + wav2vec2 LV60K，CTC 维特比 | — | `analysis/ctc_align.py` |
| 拍网格、小节 | 自己拟合的恒速网格（librosa 起音） | — | `analysis/analyze.py` |
| 段落草稿 | **SongFormer**（新增，可选） | 代码和权重 CC BY 4.0；依赖的 MuQ 权重 **CC-BY-NC 4.0** | `analysis/structure.py` |
| 角色遮罩 | anime-seg ISNet | Apache-2.0 | `tools/assets/layers.py`、`cutout.py` |
| 深度图 | **Depth Anything V2 Small**（原来是 Large） | Apache-2.0 | `tools/assets/layers.py`（`--large` 换回 Large） |

## 2026-10-08 的对比

对比脚本、数值结果和深度 / 抠图对照图在 `analysis/work/compare/`（不进 git）；分离出的音频和落选模型的权重已删。

### 换了的

- **深度：V2 Large → V2 Small**。Large 的权重是 CC-BY-NC（不能商用），Small 是 Apache。15 张主视觉图（Still_Shining 8 张 + 暗叫 7 张）上，两者深度图的相关系数是 0.87–0.999，多数在 0.96 以上，并排看几乎分不出来，暗叫 c_rider 的车轮 Small 反而更清楚。
- **新增段落草稿：SongFormer**。以前 `SECTION_BARS` 全靠看 `--bars` 表加听感手填。它自动找到的边界和人工定的分段比（±3 秒内）：Clarity 10/11、暗叫 8/8、pdoom 10/13、Falling_Again 4/7；标签（verse / pre-chorus / chorus / outro）也对得上。Still_Shining 的人工分段只标了片尾几段，比不出来。

### 试了没换的

| 候选 | 对比结果 | 结论 |
|---|---|---|
| Kim Mel-Band RoFormer（MIT，官方 SDR 12.6 vs 10.2） | 人声轨里的低频（<90 Hz）和鼓点泄漏，新旧都接近零；歌词空档段的残留也只差 0–1 dB。现有 Kim_Vocal_2 在这几首上已经够干净 | 不换 |
| Qwen3-ForcedAligner-0.6B（Apache） | 和验收过的逐词时间比，偏差中位数 Clarity 356 ms、Still_Shining 67 ms、Falling_Again 360 ms，最差 10% 超过 0.6–1.9 s。官方表里它只标了「语音」，没标「歌声」 | 不换。中日文歌暂时没有素材可测 |
| beat_this（MIT） | 主体段落和拍网格一致（拍 F 值 0.87–1.00），分歧全在前奏 / 间奏 / 尾奏这些稀疏段：漏拍、多拍、小节头认错；整体晚 13–16 ms | 不换。拍网格本来就用节拍校验片人工锁定 |
| ToonOut（BiRefNet 动漫微调，MIT） | 灰底角色图（`cutout.py` 的实际用法）和 anime-seg 的 IoU 0.98–0.99；复杂背景边缘更锐，但会把飘着的碎片抠进来，倒影画面整张当前景，没有角色的图也乱抠 | 不换 |
| Depth Anything 3（DA3-LARGE-1.1，Apache） | 比 V2 糊，头发外有一圈光晕 | 不用 |

## 坑

- **主环境的 audio-separator 0.47（Python 3.14）跑 RoFormer 系列会输出静音人声**（-75 dB，"other" 轨就是原曲），Kim_Vocal_2（MDX）不受影响。以后要用 RoFormer，先在 Python 3.12 + audio-separator 0.30 的环境里试。
- **`cv2.imwrite` / `cv2.imread` 遇到中文路径会静默失败**（返回 False，不报错），项目都在「视频项目」下。写文件用 `cv2.imencode(".png", img)[1].tofile(path)`，读用 `cv2.imdecode(np.fromfile(path, np.uint8), -1)`。`layers.py` 之前就是这样写不出 `matte.png` / `depth.png`，已修。
- SongFormer 在 12 GB 显存上跑 5 分钟的歌会爆显存：MuQ 一次处理 420 秒窗口，注意力矩阵在 fp32 下要 3.3 GB。`structure.py` 已经处理了：MuQ 的注意力换成 SDPA（数学上等价），MuQ 用 bf16（fp16 会溢出成空结果）。

## 许可提醒

- 成片里不会出现任何模型的输出（音频分离和段落只用来做分析和规划），但 CC-BY-NC 写的是「不得用于商业目的」。接商单或开收益的片子，避开 V2 Large（`--large`）和 SongFormer（MuQ 权重），段落改回手填。
- 换模型前先看许可：HuggingFace 模型页的 `license` 字段，以及它依赖的其他模型的权重许可（SongFormer 本身 CC BY，但依赖的 MuQ 是 NC）。
