# 新项目流程

从一首歌到发布，三步：**节拍校验片 → 一段成片质量的样片 → 整片**。命令都在项目根目录运行，除非写了 `cd app`。

> 为什么是这三步（2026-10-17 改，原来是六步）：六步流程每步给 2–3 个草稿候选让用户挑，用户是看质感下判断的，草稿只会被说“粗糙”“像 PPT”，推翻没少、只是提前了、变多了。做得顺的片子都是用户放权、Claude 自己定方向、直接拿成片质量说话。所以：方向自己定，第一次给用户看的就是成片质量的一段；粗排、对照、检查这些是自己用的工具，不是给用户的关卡。

| 步 | 做什么 | 给用户看 |
|---|---|---|
| 1 | 音频数据 + 节拍校验片 | `render.ts beatcheck`：小节、段落、drop 对不对 |
| 2 | 样片：自己定方向，做一段 10–15 秒、带声音、成片质量 | 样片。用户认可的这一段就是全片的画面标准 |
| 3 | 整片：整首歌排完、做完，出一版完整草稿，按意见改，发布 | 完整草稿；之后只剩局部修改 |

规矩：

- **方向自己定**：从歌和用户给的主题出发，选一个自己最有把握做好的方向直接做，不先列一排方案让用户挑。真拿不准时最多再做一段风格明显不同的对照样片
- **不先出概念图**：不用 Codex 概念图定方向、当画面靶子（代码画面拿去跟一张画比，永远是“质感不行”）。Codex 只用来做贴图、道具、背景这类素材
- **扬长避短**：光、运镜、线条、排版、抽象图形、镜头运动是强项；代码画的人物（尤其特写、表演）、纸片剪贴、拿图片拆层做视差动，以前都被说过廉价 / 像 PPT（2026-10 照 mg-styles-15 补了拼贴的做法：真纸纹、剪刀边、按拍步进、影子随高度，见效果库 `?paper`，还没在片子里用过）。主题需要人时，用剪影、远景、局部、物件和光去暗示
- **意见记进项目的 `docs/TREATMENT.md`**，标范围（这一镜 / 这一段 / 全片）。模糊的意见（“不够高级”）先按最可能的原因在那一处改一版给用户看，不把一句话放大成全片改动
- **每次给用户看就提交一次**（`git tag v2-sample` 之类当基准），不整份复制版本目录
- 效果库（字符画、字符粒子、万花筒、云海、体素、纸片和拼贴、手绘线、MG 动作、花字和 HUD、液态、玻璃、预渲染序列帧、MMD 角色、shaders 库……）在基础引擎 `app/src/library/`，用户点名要某种效果时再去拿（目录见那里的 `README.md`）；CRT、故障、VHS、像素化这些后期参数在核心的 `post.ts` 里，默认关

## 准备：建项目、定规格

```bash
python <引擎目录>/tools/new_project.py <新项目目录> [--vertical]
cd <新项目目录>/app && bun install
```

新项目里会生成 `CLAUDE.md`（指回基础引擎的文档）和 `docs/TREATMENT.md`；参考视频放 `refs/`（不进仓库）。

改 `app/src/config.ts`：画布尺寸（横 1920×1080 / 竖 1080×1920）、视频起止（截取片段）、输出文件名；母带很响时填 `AUDIO_FILTER`。平台、画幅、时长写进 TREATMENT。`app/src/engine/palette.ts` 的颜色是中性占位，定了方向就换成这支片的。

## 1. 音频数据 + 节拍校验片

1. 歌放成 `audio/song.wav`（44.1 kHz；剪辑版先剪好再放）
2. 内嵌歌词**直接写文件，不打印**：`ffprobe -v quiet -show_entries format_tags=LYRICS -of default=nw=1:nk=1 歌.flac > data/lyrics.src.lrc`
3. 分离：`python analysis/separate.py vocals`，`python analysis/separate.py demucs`
4. 节拍和包络：先 `python analysis/analyze.py` 出拍网格，**先看它打印的速度和底鼓残差（`kick residual sd`、`drift`），和听感对一下再往下**：速度是在 60–200 BPM 里自动找的，半速、倍速、4:3 这些被排除的理由列在候选表里，不对就在 `analysis/analyze.py` 开头填 `BPM_HINT`（大概的速度）重跑；残差一般 5–15 ms，`drift` 从某段起突然变大是中途变速。然后 `python analysis/structure.py` 出段落草稿（SongFormer，打印吸附到小节线的 `SECTION_BARS` 草稿；接商单的片子不用，见 `docs/模型选型.md`）；再 `python analysis/analyze.py --bars` 看每小节的表，对照草稿按听感填 `SECTION_BARS`，最后 `python analysis/analyze.py`
5. 歌词对齐：`python analysis/ctc_align.py`（长歌用 `CTC_T0` / `CTC_T1` 分段）；合成人声再跑 `analysis/snap_words.py`
6. 声音事件：`python analysis/events.py --bars`，阈值不准就调。找人声切片时要避开唱词，所以排在歌词对齐之后；歌词时间改过就重跑
7. 检查：`cd app && bun scripts/render.ts info`（只列行号、时间、字数）
8. **节拍校验片**：`cd app && bun scripts/render.ts beatcheck` → `out/check/beatcheck.mp4`。黑底配原曲：大号小节号、四拍方块、段落条、鼓点和事件的卷帘、包络、歌词行（只显示行号）。发给用户听：数字是不是跳在强拍上、段落名对不对、drop 在哪个小节（Falling_Again 的 drop 判早 1.55 秒、Clarity 切点早一小节，都是看成片才发现的）

纯音乐不需要 2、5 两步，引擎没有歌词文件也能跑；`events.py` 见人声轨比整曲低 30 dB 以上就当纯音乐，不出人声切片。

Python 依赖：numpy、scipy、librosa、soundfile、torch、torchaudio、audio-separator、opencv-python、Pillow、fonttools。

## 2. 样片

- 挑最能代表全片的一段（通常是 drop 或副歌开头），10–15 秒、连续的一段音乐、带声音、做到成片质量：`render.ts video --from a --to b --samples auto --max-samples 36`
- 写场景前读 `docs/引擎指南.md`（一页：骨架和必守的规矩），细节按需查 `docs/引擎参考.md`。后期默认全关，要泛光、颗粒、高光压缩就自己在场景里打开
- 静帧：`bun scripts/render.ts stills --t 12.5,13 --only 场景id`，渲完**亲眼看 PNG**；再带音乐原速看整段
- TREATMENT 写清方向、一句话、配色、字体、风格标志特征（写成能检验的数字；模板里用不上的节删掉）
- 给用户看之前做一轮独立评审（`docs/质量验收.md` 第四节）：另开会话当评委挑刺，按意见改到没有致命问题
- 给用户看。用户认可的这一段就是全片的画面标准，之后“质感不够”都拿它对照着改；不认可就按意见改这一段，或换方向重做一段
- 用户给了参考片、要复刻它的镜头时，按 `docs/复刻配方.md` 第五节对照（单帧像 + 连贯 + 运动量接近）

## 3. 整片

- 在 `app/src/timeline.ts` 按小节排场景（`audio.timeOfBar(k)`），删掉示例场景 `scenes/demo*.ts`
- 先把整首歌排一遍再精做：可以用 `render.ts animatic`（角标带小节号、镜头 id、段落）自己看结构和节奏——整片有没有起伏（密度、景别、色调）、切点接不接得上（`python tools/qa/seams.py out/animatic/animatic.mp4`）。这是自己的检查工具，不必停下来给用户看占位色块
- 一段段做到样片的质量，过一轮独立评审，再出一版完整草稿给用户看（`render.ts video` 全片，`--samples 1` 也行，画面是真的、只是渲得快）；之后按意见局部改
- 关键动作登记到场景的 `cues()`，用 `render.ts cues` + `tools/qa/cuecheck.py` 查卡点
- 中文字体只留用到的字：改了歌词或场景里的中文，跑一次 `python analysis/make_fonts_zh.py`（开发中可加 `--gb2312`）；`cd app && bun scripts/render.ts glyphs` 应为 0

成片和发布：

```bash
cd app && bun scripts/render-par.ts --samples auto --max-samples 36 --shutter 0.5 --out ../out/draft/v1.mp4
cd .. && python tools/qa/review.py out/draft/v1.mp4 --start <VIDEO_START>
python tools/qa/check_video.py out/draft/v1.mp4 --douyin out/qa/douyin_test.mp4   # 响度、音画偏移、空帧、色彩标签（闪光只供参考，要看加 --flash）
python tools/qa/seams.py out/draft/v1.mp4 --start <VIDEO_START>                      # 每个切点的接缝
cd app && bun scripts/render.ts glyphs                                               # 缺字
```

先带音乐、原速、从头到尾连着看一遍成片，再看报告，按 `docs/质量验收.md` 查缺陷。

- 抖音版：`python tools/douyin_mux.py <画面.mp4> audio/song.wav -o out/歌名_抖音版.mp4 [--audio-downbeat N]`
- 封面：`python tools/cover_title.py <4K 静帧> --line1 ... --line2 ...`
