# 做片指南：从一首歌到一支成片

写给做片的人看，不用懂代码。按做片的先后顺序走，每一步讲四件事：**为什么**、**跟 Claude 怎么说**（可以直接抄）、**引擎替你做了什么**、**你要看什么**。

Agent 查工具用的是[能力地图](README.md)，这页不重复那些命令细节。哪一步用不上就跳过，顺序也可以换。

---

## 先懂一件事：引擎管什么，不管什么

现在的模型自己就能写代码做出好看的画面，画面好坏主要取决于点子。所以引擎**不负责让画面更好看**，它像模型的器官：耳朵、眼睛、手和记性，负责模型自己做不到、记不住、看不见的那些事，帮你把流程走顺、少返工：

| 模型自己的短板 | 引擎补上的 |
|---|---|
| 听不到歌 | 把歌拆成数据：节拍、段落、鼓点、每个字唱在第几秒 |
| 录屏导出容易掉帧、音画错位 | 一帧一帧地渲染，第 8 秒永远是同一张画面，声音对得上 |
| 会话一长就忘了你说过什么 | 把你的原话记进项目里的 `docs/TREATMENT.md`，开工前重读 |
| 改一版就把上一版盖掉 | 每一版都留着，你逐段挑，满意的段落锁住，之后再改也动不到 |
| 看不见动起来的样子 | 抽帧拼图、运动曲线、洋葱皮（一段动作叠成一张图），把“动起来什么样”变成能看的图 |
| 交付前漏掉技术问题 | 一条命令查色彩、音量峰值、音画偏移、闪光、卡点 |

另外还有一套像 AE 那样的零件（图层、关键帧、文字动画、形状、效果、摄像机）和以前几支片留下的效果库，Claude 觉得合适就用，不合适就自己写。

## 第 1 步：建项目，分析歌，确认分析对不对

**为什么**：后面所有卡点、歌词、分段，都靠这一步拆出来的数据。自动分析偶尔会把 drop 判早一秒、把小节切错一格，这种错到成片才发现就得整段重卡，所以先花两分钟听一遍确认片。

**跟 Claude 说**：

```
用 AGENT视频基础引擎给《歌名》建一个新项目，放在 视频项目\歌名，带上 app。
歌在 <歌的路径>。先分析歌，再出分析确认片和歌词确认片给我听。
```

要竖屏（抖音）就加一句“做竖屏”。

**引擎替你做了什么**：

- 建好项目文件夹：歌放 `audio/`，分析结果放 `data/`，参考片放 `refs/`，渲出来的东西放 `out/`，版本放 `film/`
- 分析歌：节拍和速度、段落（前奏、主歌、副歌、drop……）、鼓点和声音事件、逐词歌词（中日韩英都行）
- 歌词只写进文件，不在对话里出现

**你要看什么**（带声音看）：

- **分析确认片**：大数字每个强拍跳一下，下面标着鼓点、人声和段落。听数字是不是踩在拍上、段落名和你听到的一致不一致、drop 落在哪一小节。不对就说“drop 应该在第 17 小节”“速度是 134”，Claude 改提示后重跑
- **歌词确认片**：字一个一个点亮，看是不是跟唱的对得上。对不上就说哪一句、早了还是晚了

两样都对上了再往下走。

---

## 第 2 步：拿现成的成片对齐方向

**为什么**：方向没对齐是返工最多、代价最大的原因，一否就是整版。概念图和粗分镜常常看不出最终好坏，直接拿**已经做好的片子**来对齐更准：别人的片、你的旧作、之前的版本都行。

**跟 Claude 说**：

```
我想要的感觉在这几支参考片里：
- <参考片 1>，第 10–25 秒，要的是它的节奏和转场，不要它的配色
- <参考片 2>，要的是字的出场方式
放进挑选页，我再看一遍告诉你要哪些。
```

不知道自己想要什么时，就说“拿两三支现成的片子给我挑”。真的想让它自由发挥，就说“你定”，它会直接做样片。

**引擎替你做了什么**：参考片收进挑选页，你可以带声音看；参考片只放在本机，不进仓库、不发布。你说过的话会连同日期和范围记进 `docs/TREATMENT.md`。

**你要看什么**：在挑选页里说清“要”和“不要”分别是哪一点。说不出哪里不好时，就直接指一支片：“比这支差”。

> 经验：开工前给两三支参考，方向级的退回会少很多。连着两轮方向都被否，就停下来补参考，不要再猜第三版。

---

## 第 3 步：说清楚意图和规格

说不清也没关系，Claude 会按引擎里的“开工引导”一步步跟你确认，每次只问一两件事，给你看选项或参考，你点头了再往下。

**为什么**：“做一个视频”可能做出网页、GIF 或只是一份构想。一开始把成品规格说死，Claude 才会把导出、平台适配这些活一起算进去。

**跟 Claude 说**（填空）：

```
画面方向【我来定，想要这几幕：…… / 你来定 / 你出几个方向我挑】。
做歌的【第几秒到第几秒 / 整首】，【横屏 16:9 / 竖屏 9:16】，发【B 站 / 抖音】。
给【谁】看，看完要记住【一种感觉 / 一个画面】。
最后交付：成片 MP4、封面、抖音版（如果要）。
目标【先出个样子 / 正常发布 / 商业级、冲奖，评审打到几分】。
```

目标说的是要做到什么水准。多做几个方向给你挑、查论文攻难点、多轮独立评审、高画质渲染，片子需要时 Claude 会自己用；只想先看个样子就说一声。

**引擎替你做了什么**：画布尺寸、用歌的哪一段记进项目设置；要抖音版时，最后会单独出一版合规格的。

---

## 第 4 步：定故事，让它跟着歌走

**为什么**：画面再好，跟歌没关系也会整版作废。评审打分高不代表你认可。

**跟 Claude 说**：

```
先按歌的段落和歌词意思排一个故事线，每段一两句话：这段画面是什么、情绪到哪。
最响的那段画面要最满。先给我看故事线，别急着做画面。
```

**引擎替你做了什么**：歌已经按段落切好，Claude 能按段落、按歌词行号去对意思，不用把歌词抄进对话。

**你要看什么**：每一段的画面和那段歌是不是一回事。这一步改几句话的成本最低，到成片阶段再改就是整段重做。

> 经验：卡点不等于每拍都动。每小节一切、每拍一跳会像节拍器。大的落点卡死，中间留出喘气的地方。

---

## 第 5 步：让 Claude 搭画面

**为什么**：这一步最花时间，也最容易“看着糙”。

**跟 Claude 说**：

```
按 TREATMENT 里定的方向做第 1 段。
主要的东西（角色 / 物件 / 场景）要细，不要用简单的方块和球拼。
关键段落同时做两三个不同方向，放进挑选页让我挑。
```

**引擎替你做了什么**：

- 零件：图层、关键帧和缓动、文字动画、形状、效果、3D 摄像机，Blender 出的镜头和模型也能放进来
- 生图、抠图、拆层工具；需要工厂设备、人物、叉车这类 3D 模型时，可以用你的模型库
- 几个方向并行做：每个子代理各做一版，互不干扰，做完都收进挑选页

**你要看什么**：主物件糙不糙。“粗糙”多半是场景里的东西本身做得简单，而不是画质参数的问题。

> 经验：多做再删。候选做得比要用的多，在成片里挑，比反复猜一版省事。

---

## 第 6 步：在挑选页里看、挑、锁

**为什么**：一段一段单看都没问题，连起来才发现“割裂”，这是很常见的返工原因。改一版又把你喜欢的东西冲掉，也是。

**跟 Claude 说**：

```
把新版收进来，开挑选页，再拼一条连播给我。
```

**挑选页怎么用**：

- 顶部是进度和“下一个待定”：哪些段还没选、Claude 在等你回答哪些段
- 切版本只是看（数字键 **1–9** 直接切）；按 **Enter** 选中正在看的那版，按 **L** 锁定，按 **V** 几版并列在同一个时钟上一起播
- **空格** 播放，**[ ]** 换上一段 / 下一段，**N** 跳到下一个待定，← → 跳 1 秒，↑ ↓ 调音量
- 看到喜欢的瞬间点 **“记下这一刻”**（或按 **M**）：你喜欢的常常是各版里零零散散的几秒
- Claude 写了“我打算……”的段落会显示 **对 / 不对**，点一下就行

**引擎替你做了什么**：每一版都留着，不覆盖；锁住的段落之后每收一版都会自动比对，动到了会报出来；没标的段落一律算“没认可”，不会被当成能照搬的；要退回某一版随时能找回当时的代码。

**你要看什么**：**连播**，不只看改了的那一段。带声音、原速、从头看到尾。

---

## 第 7 步：提修改意见

**为什么**：模糊的意见最容易让 Claude 猜错，一猜错就是整版重来。

**好用的写法：时间点 + 问题 + 想要的样子 + 别的别动**

```
第 6–9 秒：标题和图标挤在一起。让图标先进来，标题后出。
第 12 秒：镜头太近，人物右边被切掉了。拉远一点，人要完整。
结尾：字停得太短，我还没读完。
其他段落我满意，只改这三处。
```

**几个小提醒**：

- 一句口味只管它说的那一处。你说“这里太花了”，Claude 不会把它当成全片都要简洁的规矩。要管全片就明说“全片都这样”
- 说不清哪里不对时，可以只说感觉（“不够高级”），Claude 会按最可能的原因在那一处改一版给你看
- 改方向前 Claude 会先在挑选页写“我打算……”，你点 **对 / 不对**，确认了再动手

---

## 第 8 步：交付前检查

**跟 Claude 说**：

```
跑一遍交付自检，再找个独立评审看一遍。有缺陷直接改；动到画面口味的先问我。
```

**引擎替你做了什么**：

- 交付自检：色彩标准、音量峰值、音画偏移、闪光、卡点偏差。这些是技术问题，过不去会报出来
- 看片材料：联系表、运动量和歌的响度对照、动作最大的几处叠成洋葱皮
- 独立评审：另开一个 Agent 用新眼睛看，能挑出“看着普通”这种自己看不出的问题。但它也改坏过东西，所以锁住的段落评审不碰，评分也不决定要不要继续改

**你要看什么**：**Claude 听不到声音**，卡没卡上、好不好听只能靠你。交付前请自己带声音完整看一遍。

---

## 第 9 步：交付

**跟 Claude 说**：

```
出正式版、抖音版和封面，CREDITS 里写清用到的引擎、字体、开源代码和素材。
```

**引擎替你做了什么**：

- 正式版：帧数精确，可以加片头卡片
- 抖音版：调好音量峰值，可加锐化（防平台机审判“画质模糊”）
- 封面：从高清静帧裁出横版、竖版（或 B 站 16:9），排上标题；也可以按这支片单独设计
- `CREDITS`：引擎核心来自 pdoom-video（MIT），着色器来自 shader-effects-inc/shaders（MIT）

## 想自己上手调的时候

- **打开预览**：让 Claude “开预览”。空格播放，← → 跳 1 秒，`,` `.` 逐帧
- **自己拖动作**：预览里按 **g** 打开曲线编辑器，直接拖关键帧和手柄，存下来以后导出就照你拖的渲
- **觉得动作在飘**：跟 Claude 说“这段动作在飘，要快出慢停”。AE 那种利落靠的是不对称的缓动：快快出去、慢慢停住

## 常用说法速查

| 想要 | 说 |
|---|---|
| 开工 | “用 AGENT视频基础引擎给《歌名》建项目，歌在 …，先分析” |
| 对齐方向 | “拿两三支现成的片子给我挑” / “我想要参考片 X 第几秒的 Y” |
| 自由发挥 | “你定，直接出样片” |
| 多几个选择 | “这段同时做三个不同方向，放进挑选页” |
| 看整体 | “拼一条连播给我” |
| 定下来 | “第 3 段用 v5，锁住” |
| 改一处 | “第几秒：什么问题，想要什么，别的别动” |
| 回到以前 | “退回 v12 那版的第 2 段” |
| 交付 | “跑自检，出正式版、抖音版和封面” |

## 项目文件夹里有什么

| 位置 | 是什么 |
|---|---|
| `docs/TREATMENT.md` | 这支片的方向、参考片、你说过的话，Claude 每次开工前重读 |
| `audio/`、`data/` | 歌和分析出来的数据 |
| `refs/` | 参考片，只在本机 |
| `film/` | 所有版本、你的选择和锁定、连播 |
| `out/` | 渲出来的片段、检查材料、成片 |
| `app/` | 画面的代码（用 app 做画面时才有） |
