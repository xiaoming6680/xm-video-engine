# 场景渲染（app）

`app/` 是其中一种做画面的办法：TypeScript + three.js + Canvas 2D + 着色器，浏览器里逐帧渲染。适合排版、动效、着色器和轻量 3D，改完能马上预览。重 3D 也可以用 Blender 出序列帧（`tools/blender/`），直接成片或当底板放进来（`engine/plate.ts`）；Blender 导出的 GLB 模型能直接读（`engine/model.ts`）。

这页讲的是 `app/` 渲染器和可选的 AE 式零件；画面怎么做由你定，不用这些零件也行。只有写 app 场景才需要读这页。要用它：`python <引擎>/tools/new_project.py <项目> app`，再 `cd app && bun install`。

## 跑起来

`bunx vite`，打开打印的地址。空格播放，← → 跳 1 秒（Shift 跳 5 秒），`,` `.` 逐帧，`[` `]` 上下一个场景，`l` 循环当前场景，`h` 隐藏界面，`g` 曲线编辑器（见下面「动作」）；`?t=12` 从第 12 秒开始。

项目设置在 `src/config.ts`：画布、视频起止、音频滤镜、署名、额外字体。颜色在 `src/engine/palette.ts`（默认是中性占位）。示例场景 `scenes/demo*.ts` 不用了就删。

## 骨架

一个场景就是 `app/src/scenes/<name>.ts`，默认导出一个继承 `Scene` 的类；时间线在 `src/timeline.ts`：首尾相接是硬切，重叠是交叉淡化。

```ts
import * as THREE from 'three';
import { Scene, type Frame } from '../engine/scene';
import { FSPass, Layer2D, W, H } from '../engine/gl';

export default class MyScene extends Scene {
  bg = new FSPass(`uniform float t; void main(){ fragColor = vec4(C_INK, 1.0); }`, { t: { value: 0 } });
  text = new Layer2D();
  async init() { /* 构建几何体、预计算文字轮廓等 */ }
  render(f: Frame, out: THREE.WebGLRenderTarget) {
    const { renderer, comp } = this.ctx;
    this.bg.u.t!.value = f.t;
    this.bg.render(renderer, out);                 // 全屏着色器 → out
    const c = this.text.ctx; this.text.clear();    // 用 Canvas2D 绘制
    comp.draw(renderer, this.text.upload(), out);  // 叠到 out 上
    return { bloom: 0.7 };                         // 可选：后期参数
  }
}
```

```ts
return [
  E('intro', 'pulse', 0, au.timeOfBar(8)),            // 场景 id、场景文件名、开始、结束（歌曲秒）
  E('drop',  'city',  au.timeOfBar(8), au.duration),
];
```

## 技术约束

不是审美要求，违反了导出就会出错：

1. **输出只取决于 `f.t`。** 随机带种子（`mulberry32`、`hash`），不用 `Math.random()`、`Date.now()`。导出时一帧平均许多子帧，顺序任意。逐帧闪烁用 `frameIdx(t)`；平面色块、字用 `shutterT(t, 0)` 不被糊掉；按拍步进的每秒张数要整除帧率（60：30、20、15、12、10、6）。确实要积分的设 `stateful = true`
2. **线性 HDR，后期默认全关。** `render()` 必须完整覆盖 `out`；线性 1 就是纯白。颜色用调色板（GLSL `C_INK`，Canvas `rgba('x', a)`，GL `LIN.x`）
3. **按逻辑像素排版。** 用 `W`×`H`，4K 由引擎放大（`--scale 2`）；`fwidth` 定宽的线写成 `pxLine`，会被放大的离屏 canvas 做成 `SCALE` 倍
4. **中文字体只裁用到的字。** 改了中文就在项目根目录跑 `python <引擎>/analysis/make_fonts_zh.py`，`render.ts glyphs` 查缺字；项目自己的字体放 `app/public/fonts/src/zh/`，登记 `config.ts` 的 `EXTRA_FONTS`

渲完亲眼看：`bun scripts/render.ts stills --t 12.5,13 --only 条目`，用 Read 打开 PNG；读一读打印的 `SCENE ERRORS`。

## 场景能拿到什么

| 写法 | 是什么 |
|---|---|
| `f.t`、`f.lt`、`f.p` | 歌曲秒、场景内时间、场景进度 0–1 |
| `f.beat`、`f.bar`、`f.beatPhase`、`f.barPhase` | 第几拍、第几小节（连续值），这一拍、这一小节走了多少 |
| `f.a.kick`、`f.a.snare`、`f.a.hat` | 刚响时为 1，随后衰减 |
| `f.a.rms`、`f.a.low`、`f.a.vocal`、`f.a.drums`…… | 能量 0–1 |
| `this.ctx.lyrics` | 歌词，见下面「数据」 |
| `this.ctx.audio` | 节拍表：`timeOfBar(k)`、`nearestBeat(t)`、`events('kick', t0, t1)` |

## 命令

- 开发服务器：`cd app && bunx vite --port 5173`（5173 被别的项目占用时 Vite 会换端口，看它打印的地址）。预览：<http://localhost:5173/?t=23.0>（空格 = 播放/暂停，←/→ = ±1 秒，shift = ±5 秒，`,`/`.` = ±1 帧，`[`/`]` = 上一个/下一个时间线条目，`l` = 循环当前条目，`h` = 隐藏界面）。
- 静帧（检查成果的主要方式，渲完用 Read 工具看 PNG）：`cd app && bun scripts/render.ts stills --t 12.5,13.0,14.2 --only open --out ../out/wip/open`
- 某段时间范围的缩略图拼版：`bun scripts/render.ts sheet --from 1.5 --to 9 --n 16 --cols 4 --only open --out ../out/wip/open/sheet.png`
- 短视频片段（用来判断运动效果：渲出来用 `review.py onion` / `strip` 和 `render.ts curves` 看，不要只相信数学）：`bun scripts/render.ts video --from 20 --to 25 --only hook --out ../out/wip/hook.mp4 --preset veryfast`
- 候选：`--query swap=<条目>:<场景文件>` 让这个条目临时渲另一个场景（同样的时间窗和参数），几个子代理各写各的场景、各渲各的，不用改 `timeline.ts`
- `--only a,b` 只加载这几个时间线条目（速度快，也能把写坏的场景隔离开）。没有匹配的条目就什么都不渲染（黑屏），所以这个条目必须在 `src/timeline.ts` 里存在。
- 只对你自己的文件做类型检查：`bunx tsc --noEmit -p tsconfig.json 2>&1 | grep scenes/yourscene`。
- 渲染脚本会打印 `SCENE ERRORS` 和浏览器控制台错误——要读一读。
- 4K：在任意模式后面加 `--scale 2`（此时 `stills` 保存两倍尺寸的全分辨率 PNG，1920×1080 的项目就是 3840×2160）。两种缩放下都要检查你的场景：缩小之后，4K 画面应当和 1080p 的一样，只是更清晰。
- 渲染脚本默认每次自己启动一个不带热重载的私有服务器（几个项目共用这套引擎，5173 上跑的未必是这个项目），端口从 5300–5799 里挑没人占的；万一被别的项目抢先占了，脚本会报错让你重跑，不会渲出别的项目的画面。要复用一个已经开着的服务器就传 `--url`，它必须是**这个项目**的、不带热重载的（`PDOOM_NO_HMR=1 bunx vite --port 5190`），否则渲染中途改文件会重新加载页面。
- 停渲染：Ctrl+C、结束进程，或者只停掉启动它的 shell（后台任务被停、终端关了），`render.ts` / `render-par.ts` 都会把自己起的 vite、ffmpeg、无头 Edge 和各分段一起收掉（盯着启动它的那几层 shell，1.5 秒内退出；`--no-watch` 不盯）。以前的版本只停 shell 时这些都会接着跑、占着 `out/<名>.seg`：`bun scripts/kill-render.ts --dry` 先看，再去掉 `--dry` 结束（按命令行里的项目路径认，不碰别的项目的 vite 和渲染）。
- 卡点：`bun scripts/render.ts cues` 导出各场景登记的卡点和剪辑点，再在项目根目录 `python <引擎>/tools/qa/cuecheck.py` 看每个点离目标拍子差几毫秒。
- 连贯检查：场景覆盖 `track(t)` 报主要元素在画面上的位置，`bun scripts/render.ts track` 逐帧导出，项目根目录 `python <引擎>/tools/qa/trackcheck.py out/qa/track.json` 查瞬移、急停、交接接不上；视频本身用 `tools/qa/trail.py`（长曝光）和 `tools/qa/flowcurve.py`（运动曲线）看。
- 逐帧检查：`bun scripts/render.ts scan --from 0 --to 98 --step 0.1` 按步长渲染整段（不存图），把场景用 `console.warn` 报的问题全部打印出来。比如查走光：每帧算镜头和大腿方向的夹角（效果库 `library/engine/mmd/rig.ts` 的 `thighView`），近距离又顺着大腿看进裙子就报 `MODESTY`。
- 效果库的示例（只在基础引擎里有，`src/library/demos.ts`）：`/?sky` 云海和光束、`/?voxel` 体素字、`/?tactile` 实物感、`/?brush` 手绘线、`/?mg` MG 动作、`/?ease` AE 式缓动、`/?textanim` 文字动画器、`/?shape` 形状层、`/?blend` 混合模式和预合成、`/?layers` 图层系统和效果栈、`/?effects` 全部图层效果、`/?particles` 粒子、`/?lights` 灯光和投影、`/?pathops` 路径运算和运动路径、`/?deform` 操控点和碎裂、`/?camtrack` 3D 摄像机反求、`/?typeset` 竖排和沿路径排字、`/?reveal` 到达时间和换张、`/?caption` 花字和 HUD、`/?paper` 拼贴、`/?liquid` 液态、`/?glass` 玻璃、`/?plate` 序列帧、`/?sfx=<组件名>` shaders 库、`/?ref=<名>` 十段复刻练习（`docs/复刻配方.md` 第四节）、`/?ref=intro` 连续粗分镜、`/?ref=typewarp` 海报字的变形和进场、手绘墨线。
- `bun scripts/render.ts info` 列出时间线和每行歌词的序号、时间、字数（不输出歌词原文）。
- 缺字：`bun scripts/render.ts glyphs [--step 0.1]` 按步长渲染整段，列出画过但字体里没有的字（Canvas2D 回落到系统字体、轮廓字空白），带场景和时刻；有缺字时退出码 1。
- 别的歌：`--song refs/<名>`（预览 `?song=refs/<名>`）用这个目录的 `song.wav`、`audio.json`、`events.json`、`lyrics.json` 代替 `audio/` 和 `data/`（参考片原声，`tools/grid_song.py` 生成）；时间线比歌长时，引擎时长取时间线的结尾。
- 试后期参数：网址加 `?post=riso:1,phosphor:0.5`（`--query post=…`），覆盖所有场景自己返回的值。

## 数据

- `lyrics`（`src/engine/lyrics.ts`）：`lines[]`，每行有 `text,start,end,words[]`，每个词是 `{w,start,end}`（逐词，已与人声对齐）。取歌词行不用写死时间：`lyrics.lines[n]` 按行号，`lyrics.lineAt(t)` 取正在唱的这一句（这样代码里不用出现歌词原文）；也可以按内容查：`lyrics.get('sudden drop')` → `l.words[3].start`。辅助函数：`Lyrics.wordProgress(word, t)`（0..1 的演唱进度）、`Lyrics.lineCharProgress(line, t)`（到目前为止唱了多少个字符——用于逐字形的擦除效果）、`lyrics.findWords('P(doom)')`。
- `audio`（`src/engine/audio.ts`）：`beats[]`、`downbeats[]`、`sections[]`、`beatAt(t)`（连续的节拍序号）、`barAt(t)`、`timeOfBeat(i)`、`nearestBeat(t)`、`events('kick'|'snare'|'hat'|'vocal', t0, t1)`、`env(name, t)`（`rms|low|mid|high|vocal|drums|bass|other` 的包络，0..1）、`hit(kind, t, halfLife)`（衰减的脉冲）。
- 每个 `Frame` 都已经带着 `f.a` = `{rms,low,mid,high,vocal,drums,bass,other,kick,snare,hat,vonset}`，以及 `f.beat,f.bar,f.beatPhase,f.barPhase`。

## 场景的规则和钩子


- **确定性**：输出必须是 `f.t` 的纯函数（随机要带种子：`mulberry32(seed)`、`hash(...)`）。视觉效果里绝不能用 `Math.random()`、`Date.now()` 或 `performance.now()`。导出时每一帧要平均许多子帧，而且渲染顺序任意（见“运动模糊与采样”）。如果确实需要模拟状态（粒子、反馈缓冲），就设 `stateful = true`，在 `reset()` 里重置，用 `f.dt` 做积分，引擎会在跳转之后快进；这样的场景只能用固定的 `--samples` 导出。
- `render()` 必须完整覆盖 `out`（一个 HalfFloat 线性 HDR 渲染目标）。颜色是**线性**的。后期默认全关：泛光、光晕、色差、颗粒、暗角、高光压缩都要场景自己打开（如 `return { bloom: 0.6, shoulder: 1 }`，泛光从线性约 0.85 起）；不开时线性 1 就是纯白，超过 1 的直接截断。以前的默认（pdoom 的胶片感）是 `post.ts` 的 `PDOOM_LOOK`：时间线条目加 `post: PDOOM_LOOK`，或场景返回 `{ ...PDOOM_LOOK }`。使用调色板常量（GLSL 里用 `C_INK`、`C_BONE`、`C_SIGNAL`……；TS 里给 GL 用 `LIN.signal`；Canvas2D 用 `rgba('signal', a)`）。
- `ctx.params` 是时间线条目的参数（一个模块可以服务多个条目）；`ctx.start/ctx.end` 是它的时间窗口；`f.lt`/`f.p` 是局部时间/局部进度。
- 转场：默认情况下，引擎会给时间上重叠的条目做交叉淡化。要自定义转场，就设 `handlesTransition = true`，然后自己用 `f.tin`（在重叠期间从 0→1）去合成 `f.under`（上一个场景的画面）。两个窗口首尾相接就是硬切。
- 可以返回的后期覆盖参数（默认值都是不起作用的那一档）：`exposure, bloom, bloomThreshold, bloomKnee, bloomRadius, halation, ca, grain, vignette, shoulder（0..1 高光柔和压缩，pdoom 的胶片肩部；1 时白落在约 242）, shoulderHue（1 = 按最大通道压、粉紫高光不偏色，默认；0 = 旧的逐通道，`PDOOM_LOOK` 用）, hud（HUD 不透明度）, watermark（角落署名）, fade, flash, shake:[x,y], zoom, invert, grade, fisheye（鱼眼，配合 fisheyeFov 放大视场）, radial（径向模糊）`；复古 / 故障 / 印刷类（默认全关）：`crt, crtCurve, crtLines, crtOff, crtNoise, phosphor, glitch, glitchSeed, glitchSort, vhs, bw, bwThreshold, pixel, pixelLevels, pixelGrid, palette, paletteDither, letterbox, riso, risoDot, risoShift, risoInks, risoTrap, risoPlates, risoRough, risoDensity, risoSolid, vhsBleed, vhsTear, paperTex, paperStep`，用法和取值见 `docs/复刻配方.md`。数组参数（`palette`、`risoPlates`）不能用 `?post=` 覆盖，在场景里返回。场景自己返回 `paperTex` 时在 `init()` 里 `await loadPaper()`（时间线条目和 `?post=` 里的引擎会预载）。`phosphor`（荧光余晖）由引擎在 t − k/60 重渲画面实现，有 `stateful` 场景在屏时跳过。默认值在 `src/engine/post.ts`。
- 逐帧加载的大资源（预渲染序列帧、视频素材，`engine/plate.ts`；用在 `Comp` 的 `footage` 图层里时转给 `comp.prepare(t, t0, t1)`）：覆盖 `async prepare(t, t0, t1)`，导出时每帧渲染前引擎会等它（t0..t1 是这一帧快门覆盖的时间），预览不等；`render()` 仍是同步的，没加载好时先画上一张。Blender 镜头用 `tools/blender/render.py` 渲（按歌曲帧号 60 fps 出 EXR / PNG，同目录有 `cam.json` 和 `frames.json`，示例 `?plate=blender`）；给序列开泛光要设 `bloomKnee: 0`，不然柔和过渡会把整张序列提亮约 5 级。序列里的发光体被调色压平时，按渲染相机把它投到画面上（`tools/blender/cam_project.py`，每帧位置和视半径）在合成里补光晕；Blender 5 的坑（切点被快门拖糊、节点关键帧是 Bezier、Map Range 反向、只给反射看的灯带）见 `tools/blender/README.md`。
- 卡点登记：覆盖 `cues()`，返回 `{ t, name, on }[]`（`on`：`'downbeat'`（默认）、`'beat'` 或声音事件类型 `'kick'`、`'snare'`…）。时间轴上每个条目的开头会自动算一个剪辑点（目标是拍子）。
- 连贯运动的工具：转场想做成同一元素在变时，用关键帧层 `engine/anim.ts`（`kf` / `kfp` / `kfc`、AE 式缓动 `K`、`E` 缓动、`spring`、镜头 `follow`，见下面「动作」），让元素一直存在、沿曲线变；转场做成同一元素在变（变形 `kit/morph.ts`、推进穿过、分身、切开）。逐帧按随机数换状态能凑够运动量，但在 Running 测试里看起来是拼的。硬切的片子不需要这些。跟拍用 `lead`（领先）不用 `follow`（滞后）；缩放在对数空间插值（`kfz`），远距离转场用 `zoomPath`；形状差别大的变形用 `SlotMorph`（经过圆）；平面色块用 `shutterT(t, 0)` 保持锐利，只给飞行物模糊（示范 `?mg`）。
- 轨迹登记：覆盖 `track(t)`，返回 `{ 名字: { x, y, s?, r? } }`（画面逻辑像素），给 `render.ts track` + `tools/qa/trackcheck.py` 用；主角换了空间 / 身份时用同一个名字报，检查才知道它连着。
- 性能：目标是每帧 < 25 ms。每个 Canvas2D 图层上传一次大约要 2–4 ms；每个场景不要超过 2–3 个。能预计算的放在 `init()` 里。

## 动作：AE 式缓动、可拖的曲线、看见运动

单帧好看、动起来不像 AE，差在曲线和调的回合数。这一节的东西都不替画面做决定。

**缓动**（`engine/anim.ts`）。关键帧 `[t, v, mode]` 的第三项除了 `'auto'`（平滑）、`'ease'`、`'lin'`、`'hold'`，还可以是 AE 图表编辑器的手柄 `{ in, out, speedIn, speedOut }`：这一帧进来、出去两侧的影响（0–1，AE 的 influence ÷ 100）和速度（单位 / 秒）。常用的写法在 `K` 里：

| 想要 | 写法 |
|---|---|
| 进场、落定：快出慢停 | `[t0, a, K.go], [t1, b, K.land]` |
| 离场、蓄力：慢起快收 | `[t0, a, K.windup], [t1, b, K.slam]` |
| AE 默认缓动（F9） | `K.easy` |
| 自己给数 | `ae(进来的影响, 出去的影响, 进来的速度, 出去的速度)` |

全用 `'auto'` 的动作速度处处连续，看着在「飘」，这是代码做的动效最常见的毛病。`?ease` 示例把几种并排放，每行底下是每 1/30 秒的位置（间距图）。旧写法的结果完全不变。

**可拖的曲线**（`engine/tracks.ts`、`editor/curves.ts`）。把要细调的 `kf(t, keys)` 换成 `kfe(t, '名字', keys)`，预览里按 `g` 打开曲线编辑器：

- 拖关键帧改时间和值（Shift 只改值、Ctrl 只改时间，靠近拍点自动吸附，Alt 不吸），拖手柄改影响和速度，双击曲线加帧，Delete 删
- 按钮：缓动 F9、快出、慢停、蓄力、砸下、平滑、线性、定格、速度图（AE 的 Speed Graph）、适配、复制成代码、恢复代码；Ctrl+Z / Ctrl+Y
- 改动自动存进 `app/src/tracks.json`，代码里的关键帧只是默认值；导出读同一个文件。Agent 也可以直接改这个 json（格式就是关键帧数组），改完刷新
- 名字自动加上时间线条目的 id；只做标量，位置拆成 x、y 两条

**时间重映射**。时间线条目加 `remap`（歌曲秒 → 场景看到的秒的关键帧），整段冻结、慢放、倒放、先慢后追（AE 对预合成的 Time Remap）。它在编辑器里是一条叫「时间重映射」的可拖轨道。不要用在 `stateful` 场景上。

**看见运动**。Agent 看不到动起来的样子，靠这两样读动作：

- `bun scripts/render.ts curves [--from a --to b]`：每个场景的 `kfe` 轨道画成图（值、速度、拍、小节、切点），存在 `out/qa/curves/`，终端里逐条打出每段是「快出慢停」「对称缓动」还是「平滑穿过」，每个关键帧离拍点多少毫秒；一条轨道全是对称缓动会标「可能发飘」
- `python <引擎>/tools/qa/review.py 视频 onion 起 止 张数`：洋葱皮，一段动作叠成一张，从冷到暖着色。间距就是速度，连起来是运动弧线

## 图层：Comp、效果栈、时间线效果条

想「按层」做（AE 的合成面板）时用 `engine/layers.ts` 的 `Comp`；一笔一笔自己画照样可以，两种能混着用。示例 `/?layers`。

```ts
comp = new Comp(this.ctx, { bg: '#f4efe6', start: this.ctx.start });     // start：图层时间从这里算 0
comp.layers = [                                                           // 数组前面的在下面
  { name: 'rig', position: (t) => [960, 540], rotation: (t) => kfe(t, '整组转', spin), fps: 12 },   // 空对象，一顿一顿转
  { name: 'card', parent: 'rig', size: [600, 400], draw: (c, t) => …, effects: [{ type: 'dropShadow', offset: [10, 10], color: '#e4001c' }] },
  { name: 'flash', adjustment: true, in: 2.9, out: 2.97, effects: [{ type: 'gradientMap', stops: ['#580420', '#c1a1ad'] }] },
];
render(f, out) { this.comp.render(f.t, out); }                           // 传歌曲秒 f.t
```

- **来源**：`draw`（Canvas 2D）、`render`（往图层自己的渲染目标里画）、`texture`、`solid`、`comp`（嵌套 = 预合成）、`footage`（序列帧 / 视频素材）、`three`（three.js 场景）、`adjustment`（调整层）；什么都没有就是空对象
- **时间**：`in` / `out` 入出点，`start` 来源从哪开始，`time(t)` 时间重映射，`fps` 这一层按帧率步进（AE 的 Posterize Time，变换和效果参数一起步进），`motionBlur` 这一层拖不拖影，`echo` 残影，`cache` 内容什么时候不用重画（步进、关运动模糊的层自动复用；`'frame'` 每帧只画一次、位置照样按子帧摆，`'static'` 只画一次：层多、效果重、导出采样多时省时间）
- **变换**：`position`、`anchor`、`scale`、`rotation`、`opacity`，都能写成 `(t) => 值`；`threeD: true` 后 `z`、`rotationX`、`rotationY` 生效、过 comp 的摄像机（`camera: { zoom, position, pointOfInterest, dof }`，默认 50 mm、z = 0 时和 2D 一样大）；`parent` 跟着父层
- **镜头**：二维的推拉摇移、整幅转，就是一个空对象（没有来源的图层），别的层都 `parent` 到它，给它打帧；要透视再用 3D 图层和摄像机
- **空间（2.5D）**，示例 `/?stage`：3D 图层之间**按像素互相挡**，和 AE 一样（站在地面上的卡片、陷进地面的窗、交叉的两张面都对；Comp 的 `intersect: false` 退回整层按中心远近排；某层 `depthWrite: false` 不挡别人，给光晕、烟这类半透明的；`depthTest: false` 不被挡）。`faceCamera: true` 始终正对摄像机（AE 的朝向摄像机）。`cornerPin: [左上, 右上, 右下, 左下]` 把图层按透视钉到四个点上（AE 的 Corner Pin），点在父层的像素里，所以视频钉进一台画歪的电视屏以后跟着电视走，电视是 3D 的也行，和电视一起被挡。`comp.depthScale(z)` 给出放到深度 z 要放大几倍才和 z = 0 时一样大（往后推做视差又不想变小）。嵌套合成当 3D 图层时加 `collapse: true` 就是 AE 的**折叠变换**：里面的图层不先拍成一张平面，直接摆进外面的空间，用外面的摄像机、和外面的 3D 图层一起排序互挡，摄像机一动里面也有视差，伸出边界的也不裁（一个带纵深的窗、盒子、舞台可以做成一个合成反复用）；这层带 effects / masks / matte 时和 AE 一样只能拍平
- **按速度拉糊** `smear`：这层动多快就沿运动方向拉多长（平移拉丝、旋转、缩放都算，含父层和摄像机的运动），拖影 = 每秒的运动 × smear / 30（0.5 ≈ 180° 快门，3 是夸张的甩）。不靠导出的子帧，`--samples 1` 也有；开了它这层不再按子帧摆位置，不会糊两遍
- **厚度** `extrude`：`{ depth, offset, color, colorBack }`，同一层的剪影沿厚度叠一串、侧面平涂不打光（白面红侧的立体字、有厚度的卡片），3D 图层转身就露出侧面；`offset` 是沿图层平面挤，2D 也能用
- **合成**：`mode` 混合模式、`matte: { layer, mode }` 轨道遮罩（当遮罩的层自动隐藏）、`masks` 蒙版（路径、羽化、扩展、相加 / 相减 / 相交）、`effects` 效果栈。顺序和 AE 一样：先蒙版、后效果、再变换
- 逐帧配方（「第 0 帧 160%、第 1 帧 125%……」）给这一层 `fps: 30`，属性里用 `Math.round((t − t0) × 30)` 取第几帧

**一台摄像机：3D 图层、three.js、模型、素材摆在同一个空间里**（示例 `/?space`）。合成按 AE 用像素、y 向下；three.js 和 Blender 用米、y 向上。`engine/space.ts` 的 `Space` 在两边换算，摄像机照旧按米写：

```ts
S = new Space(W, H, { ppm: 100 });                                       // 1 米 = 100 合成像素，世界原点在合成中心
comp = new Comp(this.ctx, { space: S, camera: (t) => S.camera(path.at(t)) });   // CamPath / ShotRig / three 相机 → 合成摄像机
model = (await loadModel('/assets/models/x.glb')).fit({ height: 1.8 }).shadows();   // engine/model.ts，init 里
clip = await loadFootage(this.ctx.renderer, '/assets/footage/clip');     // tools/footage.py 抽的帧
comp.layers = [
  { name: 'world', three: { scene: world, update: (t) => model.pose(t, 'Walk') } },   // three 场景，自动用合成的摄像机渲
  { name: 'title', threeD: true, position: S.point([0, 2.4, -3]), scale: S.px(4) / 1600, size: [1600, 300], draw: … },   // 字立在世界里，被物体挡
  { name: 'screen', threeD: true, footage: clip, position: S.point([-3, 1.5, -6]), scale: S.px(3.2) / clip.width },
];
prepare(t, t0, t1) { return this.comp.prepare(t, t0, t1); }               // 有素材时：导出等帧读完
```

- `three` 层铺满整幅、用合成的摄像机渲；它**上面**的 3D 图层按像素深度被它的物体挡住（`occlude: false` 关掉，某层 `depthTest: false` 不被挡）。`update(t, cam)` 在渲之前摆动画，`render(r, out, cam, t)` 给了就自己渲（AO、描边），挡字的深度另渲一遍
- Blender 的相机：序列帧的 `cam.json` 先 `plate.applyCamera(threeCam, t)`，再 `S.camera(threeCam)` 当合成摄像机，3D 图层和 three 场景就跟着 Blender 的镜头走
- 模型：`pose(t, clip, { loop })` 按时间确定地摆动画（可混几段），`fit`、`shadows`、`find(名字)`、`clone()`；Draco / Meshopt 压缩直接能读
- 素材：`python tools/footage.py 视频 --name 名字` 抽到 `assets/footage/名字/`（`--png` 留透明，`--from/--to` 截一段）；图层尺寸 = 帧像素，`start` / `time` 照常管时间

**效果**（`engine/effects.ts`，图层的 `effects`、调整层、时间线效果条都用它，场景里也能直接 `new Fx().run(renderer, src, out, 列表)`）：模糊 `blur`、`directionalBlur`（拉丝，`side: 'back'` 只往后拖）、`radialBlur`（缩放 / 旋转）；颜色 `gradientMap`（两个颜色就是 Tint，三个是三色调）、`fill`、`levels`、`hueSat`、`invert`、`threshold`、`posterize`、`exposure`；风格化 `mosaic`、`glow`、`halftone`、`noise`；扭曲 `offset`（绕回平移）、`tile`（四周补内容，甩镜不露边）、`displace`、`wave`、`blockGlitch`、`rgbSplit`；图层样式 `dropShadow`（`softness: 0` 是硬投影）、`stroke`；`custom` 自己写一段着色器。AE 式的扩展（全表和默认值在文件开头，示例 `?effects`）：扭曲 `bulge`、`spherize`、`twirl`、`ripple`、`polar`、`bend`、`lensDistort`、`meshWarp`、`displacementMap`；转场 `linearWipe`、`radialWipe`、`irisWipe`、`venetianBlinds`、`blockDissolve`、`gradientWipe`、`pageTurn`、`cardWipe`（completion 0 完整、1 没了）；变形 `puppet`（操控点）、`shatter`（碎裂）；调色 `curves`、`colorBalance`、`brightnessContrast`、`leaveColor`；图层样式 `innerShadow`、`innerGlow`、`outerGlow`、`bevel`、`gradientOverlay`；抠像 `chromaKey`、`lumaKey`、`matteChoke`；光 `lightRays`、`lensFlare`、`lightLeak`、`glow` 的 `deep`。带点的参数按图层像素，留边时自动跟着挪。长度按逻辑像素，角度顺时针为正，参数和默认值在文件开头。颜色类在显示空间算，模糊、发光、曝光、位移在线性空间算、保留高光余量。

**时间线效果条**：时间线条目不写 `load`、写 `effects: (t, lt) => 效果列表`，就是盖在所有场景上面、能跨过切点的调整层（也能带 `post`）。切点前后几帧的变色、拉丝、冲白、反相都放这里，两边的场景不用知道彼此：

```ts
{ id: 'cut3', start: cut - 3 / 30, end: cut + 1 / 30, effects: (t) => {
  const k = frameFrom(t, cut);                       // 切点前一帧是 -1；同一帧的子帧拿到同一个数
  return k === -2 ? [{ type: 'gradientMap', stops: ['#580420', '#c1a1ad'] }] : k === -1 ? [{ type: 'directionalBlur', length: 1600 }] : [{ type: 'invert' }];
} }
```

**时间线转场**：两段在切点前后重叠，后一段写 `transition: (t, x) => 图层`，`x.from` / `x.to` 是旧、新两幅整画面（纹理），`x.lt` / `x.dur` / `x.p` 是进了重叠多久、重叠多长、进度；返回的图层随便摆，能加效果、厚度、smear，没盖住的地方是黑的。不写就是默认的交叉淡化。旧、新按这一帧的时刻换就不会混帧（用 `shutterT(t, 0)` 和切点比）。没有现成的转场，怎么转按这支片自己设计：

```ts
E('s1', 'shot_a', 0, cut + 0.25),
E('s2', 'shot_b', cut - 0.5, 8, { transition: (t, x) => shutterT(t, 0) < cut
  ? [{ texture: x.from, rotation: (tt) => …, smear: 1 }]
  : [{ texture: x.to, scale: (tt) => …, smear: 1 }] }),
```

**到达时间**（`engine/arrival.ts` + 效果 `reveal`）：给图层上每个像素一个「什么时候出现」（秒），效果栈里 `{ type: 'reveal', map, t }` 到点才显示。线稿一条一条描出来、字按笔顺写、光从一点一档一档往外亮、黑条被擦掉（`invert`），都是它，换的只是到达时间怎么算：

- `arrivalStrokes`：按笔画中心线（`timeStrokes` 按长度和抬笔距离排好时间），墨迹归最近的一笔，交叉处先写的先占；`penAt(timed, t)` 是同一个钟的笔尖位置和抬笔高度，手、笔跟着它走，笔尖就始终在出墨的地方
- `arrivalTrace`：没有笔画数据的线稿，按连着的一段一段从一头沿线走到另一头，`order` 定先后
- `arrivalDistance`：从点或一块区域往外推，`squash` 让波前成椭圆，`within` 只沿一块区域传
- `arrivalFrom`：自己写 `(x, y) => 秒`；`min` 把两张拼一起，`offset` / `stretch` 挪时间
- `reveal` 的 `soft` 是到了之后多久变满（0 硬边），`front` 把刚到的一圈染色（墨迹湿边、光的前沿）。要一档一档地出，给 `t` 套 `stepT`

```ts
const timed = timeStrokes(strokes, { start: 1.2, speed: 600 });           // strokes：每笔一串中心线点（图层像素）
const map = arrivalStrokes(600, 400, timed, { radius: 14 });
{ size: [600, 400], texture: ink, effects: (t) => [{ type: 'reveal', map, t, soft: 0.02 }] },
{ ...pen.layer(), position: (t) => { const p = penAt(timed, t); return [p.x, p.y - p.height]; } },
```

**换张**（`engine/swap.ts`）：同一个角色、道具的几张关键图一张换一张（有限动画、生成图拼出来的动态）。每张标锚点（踩地的脚、腰、笔尖），换张时锚点落在同一处，人不跳；再标 `toward`，方向和大小也对上。`keys` 定什么时候换（`Swap.seq` 按每张停多久生成），`minHold` 防换得太碎，`fps` 对齐到手绘的格子；同一帧的子帧拿同一张，换张不算运动（smear 只拉真的位移）。一个 Swap 可以给几个图层（再叠一层当影子）。

```ts
const run = new Swap(this.ctx, imgs.map((src, i) => ({ src, anchor: hips[i] })), { keys: Swap.seq(t0, [0, 1, 2, 3], beat / 4, { until: t1 }) });
{ ...run.layer(), position: (t) => [x(t), 900], scale: 0.6 },
```

参考（不是规定）：《少女A》同人 MV（GitHub RepressedAlliance/Fable5.5-YoungGirlA）里，作者最认可的就是生成图连续换张拼出来的动态。他们每张至少停 5 帧防闪，跑步 8 张两步、每张 1/4 拍、落脚踩拍，风吹头发每张 2–4 帧再逐渐放慢到 10 帧，手绘层按 1/15 s 走；开场线稿、结尾写名字、开眼时颜色从眼睛一档一档亮开，都是按到达时间出现。

示例：`/?reveal`（写字带笔、线稿描出、光一档一档扩开和擦黑条、换张对齐与不对齐对照）。

**表达式里常用的**（`engine/anim.ts`）：`wiggle(t, 频率, 幅度, seed)` / `wiggle2`（AE 的 wiggle，漂浮、手持晃）、`loopOut(t, keys, 'cycle' | 'pingpong' | 'offset' | 'continue')`。

时间线条目（场景和效果条都算）的 `post` 也可以写成 `(t, lt) => 后期参数`：一帧的震屏、慢慢退掉的闪白。效果栈里的 `transform` 是 AE 的「变换」效果：挪内容不挪图层，放在效果条里就是整幅画面撞一下。

**没有的**（有意不做，需要就自己写）：3D 图层的灯光、阴影（要受光就把东西做进 `three` 层）；折叠的合成里的 `three` 层和调整层（折叠时跳过）；图层面板式的时间线界面（Agent 用不上，调动作用曲线编辑器）。

## 工具箱

- `gl.ts`：`FSPass(frag, uniforms)`，全屏 GLSL3 渲染 pass（提供 `vUv`，输出写到 `fragColor`，自动包含 `GLSL_COMMON`）；`Compositor`（合成器），通过 `this.ctx.comp.draw(renderer, tex, target, {mode, opacity, tint, scale, offset, matte, matteMode, transform})` 调用：`mode` 有 `normal`、`add`、`screen`、`multiply`、`max`、`replace`，以及要读底色的 `overlay`、`softLight`、`hardLight`、`colorDodge`、`colorBurn`、`darken`、`lighten`、`difference`、`exclusion`（按 Photoshop 公式在显示空间算，超过 1 的高光单独保留，`target` 必须是渲染目标）；`matte` 轨道遮罩（`matteMode` 为 `alpha` / `alphaInv` / `luma` / `lumaInv`，按目标对齐取）；`transform: { position, anchor, scale, rotation, size }` 像 AE 图层一样按逻辑像素摆放（旋转用角度、顺时针为正），或 `transform: { matrix, size }` 给一个透视矩阵（3D 图层用）。详见 `gl.ts` 里 `Compositor` 一节的开头，示例 `?blend`；`Layer2D`（1920×1080 逻辑尺寸的 Canvas2D → sRGB 纹理）；`makeRT()`（屏幕尺寸的 HDR 渲染目标；`makeRT(w, h)` 的参数是逻辑像素）；`clearRT(renderer, rt, [r,g,b])`；`SCALE`/`PW`/`PH`（输出缩放倍数和物理尺寸）。
- `glsl/common.ts`（`GLSL_COMMON`，会自动加在 FSPass 前面；你自己的 ShaderMaterial 也可以导入它）：调色板常量、`hash*`、`snoise(vec2|vec3)`、`fbm`、`curl2`、2D/3D SDF、`smin`、`aaFill`、`aaStroke`、`aaGridLine` / `aaGrid`（按像素抗锯齿的网格线，远处密过像素时退成平均色调），**用来做雕版风格明暗的 `hatch(u, darkness)` 和 `engrave(uv, darkness, freq, angle)`**，`heat(x)` 信号色的热度渐变（C_INK → C_BLOOD → C_SIGNAL → C_EMBER），`toSRGB/toLinear`。
- `lines.ts`：`LineBatch(capacity, {screen2D, worldWidth, blend})` —— GPU 绘制的胶囊形线段，可以是 2D 像素坐标（y 轴向下），也可以是带相机的 3D。`seg2`、`seg`、`polyline`、`render(renderer, out, camera?)`。颜色是线性的，可以超过 1 来发光。适合 1 万到 20 万条线段的规模。
- `type.ts`：字体。**默认文字字体 `F.sans(weight 300–900)`**（Archivo 标准宽度，中文自动落到思源黑体）；`F.archivo(width 62–125, weight 300–900)`（Grotesk 无衬线体，宽度档位 62/75/87.5/100/112.5/125；100 以上是加宽字，别当默认用），`F.archivoItalic()`，`F.serif(weight, italic)`（Cormorant Garamond），`F.mono(weight, italic)`（IBM Plex Mono）。`font(family, px)` → CSS 字体字符串。`layout(text, family, size, tracking)` → 按字体自带的字偶距（kerning）算出每个字形的 x 坐标和步进（第 i 个字形画在 `glyphs[i].x`）。`glyphX(text, i, family, size)` → 一个词被拆成几段来画时（已唱/未唱不同颜色、擦除效果），`text[i..]` 应该从哪里开始画；绝不要用 `measure(text.slice(0, i))` 来偏移某一段，那样会丢掉两段之间的字偶距。`fitSize`、`measure`、`textPath2D`（opentype 轮廓转成 Path2D）、`textPathCommands`、`textPoints(text, family, size, step)`（填满字形的点——“由原子组成的文字”）。`smart(s)` / `plain(s)`：打字机引号 → 印刷引号（’ “ ” …），以及反向转换。
- 标题 / 品牌字拿不准时可以先出对比图来挑：`python <引擎>/tools/font_sheet.py --text … --font … -o out/fonts/x.jpg`（中文 `--vertical`、发光 `--glow`、可变字体的命名实例、缺字标出来）。挑中的商业字体（苹方、Mistral、华文行楷……）只放进具体项目：中文放 `app/public/fonts/src/zh/`，`analysis/make_fonts_zh.py` 裁成片中用字；再登记 `config.ts` 的 `EXTRA_FONTS`。
- 单线书写字体（绘图仪、手写体，可按演唱进度“写出来”）在效果库 `library/engine/stroke.ts`，用前在场景 `init()` 里 `await loadStrokeFonts()`。
- `textanim.ts`：AE 的文字动画器（Canvas2D）。`new TextBlock(text, style)` 排版（中英混排、`\n` 多行、字距、行距、对齐，结果缓存），`.draw(c, x, y, t, 动画器们, paint)` 画。动画器 = 选择器 + 属性：选择器有 `range`（起点、终点、偏移，按字 / 词 / 行，6 种形状，Ease High / Low，打乱顺序）、`wiggly`（每个字按噪声取值）、`cascade`（按顺序错峰出发、可过冲），可以组合；属性有位移、缩放、旋转、倾斜、透明、模糊、字距、颜色、描边、换字、乱码。给 `range` 的起点终点打 `kf` / `kfe` 就是 AE 里给范围打帧。竖排 `vertical: true`（列从右往左），沿路径排字 `paint.path` / `pathOffset`（给偏移打帧字就沿路径跑），`fill` 可以是 `CanvasPattern`（字里的网纹）。用法和全部参数在文件开头，示例 `?textanim`、`?typeset`。逐字模糊每字约 0.2 ms（4K 约 1.4 ms）；只按 `\n` 换行
- `shape.ts`：AE 的形状层（Canvas2D）。路径来自 SVG 字符串、矩形、椭圆、多边形、星形、折线（都能倒圆角）、字的轮廓 `textPath`；`drawShape(c, 路径, style, t)` 画：填充（纯色 / 渐变）、描边（虚线、起止渐细 taper）、描边生长 `trim`（start / end / offset，单位是圈，能绕回；一起算或各算各的）、路径抖动 `wiggle`、重复器 `repeater`；`PathMorph(A, B).at(u)` 路径变形。角度用弧度。用法在文件开头，示例 `?shape`。形状差得很远的变形用效果库的 `SlotMorph`

## 排版

- 比例字体的文字要用上字体自带的字偶距：通过 Canvas2D 整串绘制的字符串自动就有；逐字形绘制则必须用 `layout()` / `glyphX()`。不同字体或字号的相邻文字段之间没有字偶距：那个间隙要凭肉眼调。
- 歌词自带印刷体标点（`don’t`、`’cause`、`“Just`）：`Word.w` 和 `Line.text` 都经过 `smart()` 处理；`lyrics.get()` 同时能匹配直引号和弯引号。硬编码的显示字符串同样要用 ’ “ ” … – — × −。等宽文字（IBM Plex Mono）是界面/终端的声音，保留打字机引号（把歌词显示成键入内容时，用 `plain()`）。
- `util.ts`：`clamp, lerp, remap, smoothstep, ease.*, prog(x,a,b,ease), keys(t, [[t,v,ease],...]), springStep, pulse, mulberry32, hash, noise1/2/3, fbm1/2, polylineLengths, pointAtLength, window01, shutterT, stepT, exposure, handJitter`。
- 字距和字重的起点（参考 mg-styles-15 的科普和线条两支）：中文大标题用最粗一档、字距约 −0.01em；英文小字（栏目名、注释）字距 0.14–0.2em、灰色；英文和中文的副标题字距可以拉到 0.46–0.5em 做呼吸感。只是起点，按画面调
- `hud.ts`：角落署名（文字在 `src/config.ts` 的 `CREDIT`），场景返回 `post.watermark > 0` 时才画，默认不画。pdoom 原版的裁切标记和 P(doom) 读数已去掉。

## 输出缩放（4K）

`?scale=2`（render.ts 的 `--scale 2`）会渲染两倍尺寸的画面（1920×1080 → 3840×2160）。场景继续按 `src/config.ts` 里的逻辑尺寸排版（`W`、`H`、`ctx.W`、`ctx.H` 永远不变）；剩下的由引擎处理：

- 渲染目标：`out`、引擎自己的渲染目标以及 `makeRT()` 都是物理尺寸（`PW`×`PH`）。`makeRT(w, h)` 接收逻辑像素，分配 `w*SCALE`×`h*SCALE`；如果是分辨率不能随输出变化的数据型渲染目标，传 `{ pxScale: 1 }`。
- `Layer2D`：底层 canvas 放大了 `SCALE` 倍，它的上下文也预先缩放过，所以绘制代码照常用逻辑像素。`setTransform`/`resetTransform`/`getTransform`、`shadowBlur`、`shadowOffsetX/Y` 以及 `filter` 里的像素长度都打过补丁，保持为逻辑单位。没打补丁的：`canvas.width/height` 和 `getImageData`/`putImageData` 用的是物理像素，`drawImage(layer.canvas, x, y)` 需要显式给出尺寸。`new Layer2D(w, h, 1)` 会建一个刻意的低分辨率图层（比如柔和的辉光）。`scaleContext2D(ctx, SCALE)` 可以给你自己的 canvas 打同样的补丁。
- `LineBatch`：坐标和线宽保持逻辑单位；抗锯齿羽化和发丝线的最小线宽则按物理像素计算，所以发丝线依然锐利。
- GLSL（`GLSL_COMMON`）：`gl_FragCoord`、`fwidth` 和 `dFdx` 是物理像素。只要和逻辑尺寸一起计算，就用 `FRAG_PX`（片元在逻辑像素中的位置）代替 `gl_FragCoord.xy`，并用 `PX_SCALE` 换算。宽度由 `fwidth` 决定的线（“1.2 px 的发丝线”：`1.0 - smoothstep(a, b, d / fwidth(u))`）在 4K 下会变细、变淡：把它写成 `pxLine(d, a, b)`，它在 1× 下完全一样，在 4K 下保持与 1× 相同的墨量，只是边缘更锐利（`rampLine` 对线性渐变的写法做同样的事）。`hatch`、`engrave` 和 `aaStroke` 已经这样处理了。以像素表示的 LOD 阈值和超采样偏移量要用逻辑像素（`fwidth(u) * PX_SCALE`，偏移量 `/ PX_SCALE`）。
- 用作纹理的离屏 canvas（图集、文字平面）保持它们自己的尺寸：如果会被放大显示，就把它们做成 `SCALE` 倍大（配合 `ctx.scale(SCALE, SCALE)`），否则在 4K 下会发虚。
- 后期（bloom、halation、色差 CA、颗粒、暗角）和 HUD 会自动缩放；bloom 的降采样金字塔保持在逻辑分辨率。

## 运动模糊与采样

导出时，每一帧都渲染成许多子帧的平均值，这些子帧分布在快门时间内（`--shutter 0.2`：帧间隔的五分之一，以这一帧的时刻为中心），平均在后期处理之前完成。`--samples N` 取 N 个均匀分布的子帧；`--samples auto` 逐帧决定数量（`Engine.render`、`AdaptiveSampling`）：

- 数量按 4、12、36、108、324 逐级增加。每升一级，就在每个已有子帧的两侧各加一个子帧，所以每一组都均匀分布、并以这一帧的时刻为中心。
- 每升一级之后，引擎比较新子帧的平均值和旧子帧的平均值（比较的是最终显示值，取误差最大的 2×2 逻辑像素块）。运动边缘上一格一格的重影在两组之间会不同；已经收敛的拖影或者静止画面则不会。重影误差随 1/子帧数 缩小，所以这一帧剩下的误差大约是最后一级变化量的一半；当它低于 `--tol`（默认 3 个色阶，满量程 255）时就停止。
- 实际上，静止画面停在 12，普通的镜头运动停在 36，甩镜、重击和快速变焦停在 108 或 324。在 4K 下 1:1 查看，108 和 324 已经分辨不出，而 36 在最快的边缘上还能看到淡淡的条纹。满屏的细光线、光点（光画、城市灯）误差降不下来，几乎每帧都会跑到 `--max-samples`，这类片子要按镜头写 `maxSamples`，或者草稿用 36。
- 速度：耗时约等于子帧数乘以每个子帧的耗时。Windows 默认用 `--angle vulkan`。Direct3D 11 下每个 1920×1080 的 `Layer2D` 上传到 WebGL 要约 20 ms（GPU 进程占满一个核，显卡基本闲着），每个子帧都重画的光画层会把整帧拖慢 20 倍以上。实测一段线条很多的副歌，一帧 108 个子帧：D3D11 要 15.5 s，Vulkan 只要 0.5 s。Vulkan 和 D3D11 的画面在体积云和字的边缘上会差几个色阶，补渲旧片的分段要用当初的后端（`--angle d3d11`），不然拼接处会跳。Vulkan 下重渲同一帧会有极少数像素（不到 0.001%）出入，D3D11 是逐像素一致的，所以需要严格确定性（比如回归对比）时用 `--angle d3d11`。`render-par.ts` 默认开 4 个进程：到 3–4 个时显卡已经很忙，再多开基本只多占显存。
- 4K（`--scale 2`）：同一段副歌一个子帧要 84 ms，1080p 只要 6–10 ms，像素多 4 倍，耗时多了约 15 倍。时间花在浏览器 GPU 进程里 Skia 对 Canvas2D 的光栅化上（副歌每个子帧约 1400 次 stroke），试过的 Chrome 启动参数（MSAA、显存上限、Graphite、原生 Vulkan）都没有效果。2 个进程就到顶了（3 个也是每秒 1.4 帧），所以 4K 默认开 2 个。Canvas 线条多的片子，4K 的 108 子帧要按小时算，草稿还是先出 1080p。
- 显存：`render.ts video --from --to` 只加载和这一段重叠的场景（`main.ts ?span`），4K 下每个浏览器约省 1 GB。`render-par.ts` 启动每个分段之前会看显存（nvidia-smi），放不下就等，并留出 `--vram-reserve`（默认 1.5 GB）。万一剩余显存跌破 0.5 GB，就停掉最新的那个分段，稍后重渲。显存吃满会让 Windows 重置显卡驱动，整个桌面会卡死。

**硬切按帧走**：多采样导出时，一帧显示哪些场景按这一帧本身的时刻定，所有子帧一样；切点正好落在帧上也是干净的硬切，不会被子帧混成一帧半透明。场景拿到的子帧时间夹在自己的时间窗里（不会出现负的 `lt`）。

这对场景提出的要求：

- 子帧不按时间顺序渲染，数量也不固定：场景的输出只能依赖 `f.t`。`stateful` 场景不能做自适应采样（引擎会拒绝）；任何逻辑都不能依赖 `render()` 被调用的次数。
- 按 60 fps 逐帧变化的闪烁和抖动必须用 `frameIdx(t)`（`util.ts`），而不是 `Math.floor(t * 60)`。`frameIdx` 在这一帧的整个快门时间内保持不变；`floor` 却恰好在这一帧自己的时刻跳变，于是每一帧都会把两种状态叠印在一起。
- 逐元素快门：`shutterT(t, amount)`（`util.ts`）。平面色块、字、定格的画不该被运动模糊糊掉，用 `shutterT(t, 0)` 取这一帧的时刻；只有飞过去的东西用整个快门。`amount` 取 0.5 就是半个快门（比如镜头比飞过的东西糊得少）。预览和单采样静帧里它原样返回 `t`。传歌曲秒（`f.t`）、局部时间（`f.lt`）、带偏移的时间都行：导出时按子帧离这一帧的距离挪回去；已经取过一次的结果再传进来原样返回
- 按拍步进：`stepT(t, 每秒张数)`、摄影表 `exposure(t, [[起, 每秒张数], …])`、手放抖动 `handJitter(t, 每秒次数, 幅度, 种子)`。逐帧手绘一拍二、拼贴纸片 12 张 / 秒、机位 6 次 / 秒都用它们；它们自带 `shutterT(t, 0)`，一张画不会糊进下一张，传局部时间也对。每秒张数要能整除导出帧率（60：30、20、15、12、10、6），否则每张停的帧数不一样，动作会顿
- 停得干净：画面步进或砸完停住时，后期的颗粒默认每帧还在换，停住的帧其实在闪。返回 `grainFps`（颗粒和 8 位抖动每秒换几次，和画面步进一样，比如 12；1 = 颗粒不动）。量停住的帧占比：`review.py 视频 rhythm`
- 用法：逐帧手绘用 `celDrawing(t, sheet)`（`library/kit/tegaki.ts`），推镜时每帧先 `closeUp(zoom)`；拼贴纸片按 12 张 / 秒拍落、静止的 6 次 / 秒抖、机位 6 次 / 秒步进（`library/engine/paper.ts` 拼贴一节），相机不在纸层之间平滑穿行；重击那一帧用 `hitT(t, [时刻])`（`library/kit/termhud.ts`）关快门。这些函数都传歌曲秒 `f.t`，不传场景局部时间
- 随连续的 `t` 变化的噪声（以时间为种子的 hash）在每个子帧里都会重新采样：它最终会被平均掉，但很慢，还会让自适应采样器更费劲。除非本来就想让它平滑掉，否则用 `frameIdx(t)` 做种子。
- 发射速率随时间变化的火花发射器，要把速率写成粒子出生时间的函数，并给出最大值（`sparkParticles(..., { rate: (tb) => ..., rateMax })`）。如果读的是当前 `t` 的速率，每个粒子的时间都会在子帧之间被重新排布。
- 内部自带超采样（4 个旋转网格采样点）的着色器接收 `ssTap: SS_TAP` 和 `${SS_TAP_GLSL}`，用 `for (int k = ssK0(); k < ssK1(); k++) ... rgss(k)` 循环，按 `ssWeight()` 加权。这样引擎会给每个子帧只分一个采样点、轮流循环（每组的数量都是 4 的倍数），平均下来是同样的画面，开销只有四分之一。在预览和单采样的静帧里，它们会取全部四个点。
- 3D 网格的抗锯齿：多采样导出时（每组是 4 的倍数），透视相机的每次渲染都加一个子像素抖动，快门的每四分之一用一个旋转网格采样点（`gl.ts` 的 `jitterRenders`），网格边缘自动抗锯齿，不用开 MSAA。正交相机默认不抖（全屏 pass、2D 图层）；正交的 3D 视角（等轴）设 `cam.userData.jitter = true`，灯光的深度图这类透视相机设 `false`。相机自己的矩阵不变，`toUV` 照旧。预览和单采样静帧不抖
- 软阴影：每帧放好灯之后调 `softSun(light, 0.03)`（`world.ts`），多采样时灯的方向沿一个小圆盘上的螺旋走过整个快门，平均出离遮挡物越远越虚的半影；预览和单采样静帧是硬影。半径单位是弧度（太阳约 0.005，0.02–0.05 像柔光棚）
- 逐子帧变化、只为被平均掉的东西（抖动、软光）按 `SUBFRAME.s`（子帧在快门里的位置，0–1）取值，不要按子帧序号：自适应采样后加的子帧挨着它细化的那些，取值相近，静止的地方几组平均一致；按序号取，每组都不一样，采样器会一路加到上限（demo3d 实测从 108 个涨到 324 个）
- 后期参数（震动、闪光、缩放、淡入淡出、HUD 模式）只在快门内的一个时间点读取：这一帧时刻之后 1/8 个快门长度处（视频就是在这个点上调校的，而且每一组采样都包含这个点）；HUD、颗粒和抖色（dither）每帧只画一次。

## 常见问题

- **预览打开的是别的项目？** 5173 被占用时 Vite 会换端口，以打印的地址为准。渲染脚本自己起私有服务器，不受影响
- **没有 Edge，或在 macOS / Linux 上？** 渲染脚本加 `--channel chrome`
- **找不到 ffmpeg？** 加到 PATH，或设环境变量 `FFMPEG`
- **导出太慢？** `render-par.ts` 用 `--workers` 设进程数（默认 4，4K 默认 2）；Windows 确认没加 `--angle d3d11`；草稿 `--max-samples 36`
- **停了导出，`out/<名>.seg` 还被占着？** `bun scripts/kill-render.ts --dry` 看看，去掉 `--dry` 结束
- **改了基础引擎，已复制的 app 会变吗？** 不会，每个项目是独立拷贝

导出：

```bash
bun scripts/render.ts animatic                                                                      # 整片粗排：快速渲染，角标带小节号、镜头 id、段落，自己看结构用
bun scripts/render-par.ts --samples 1 --out ../out/draft/v1.mp4                                     # 最快的整片草稿：画面是真的，只是没有运动模糊
bun scripts/render-par.ts --samples auto --max-samples 36 --shutter 0.5 --out ../out/draft/v1.mp4   # 草稿
bun scripts/render-par.ts --samples auto --scale 2 --out ../out/final.mp4                           # 4K
```
